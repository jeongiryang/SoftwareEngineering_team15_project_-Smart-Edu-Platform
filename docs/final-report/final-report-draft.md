# Smart Edu Platform 최종보고서 초안

## 1. 프로젝트 개요

Smart Edu Platform은 웹/모바일 환경에서 개인별 학습 계획, 복습, 집중 시간, 커뮤니티, 친구 소통, 보상형 동기부여를 하나의 흐름으로 연결하는 맞춤형 학습 관리 앱이다. 팀 15는 Phase 1의 요구사항·설계 문서를 기준으로 Phase 2 구현과 테스트를 진행했으며, 최종 제출 단계에서는 구현 기능, 테스트 결과, 배포 구조, 한계와 확장 방향을 정리한다.

## 2. 주제 선정 이유

학습자는 일정 관리, 복습 기록, 질문 정리, 집중 시간 확인, 동기 유지 도구를 서로 다른 서비스에서 분리해서 사용하기 쉽다. 이 프로젝트는 학습 흐름을 끊지 않고 계획 수립부터 복습, AI 보조, 커뮤니티 소통, 보상까지 이어지는 통합 학습 관리 경험을 제공하는 것을 목표로 했다.

## 3. 요구사항 요약

- 사용자 등록/로그인과 계정 상태 관리
- 학습 일정, D-Day, 칸반 태스크 관리
- 학습 노트, 복습 퀴즈, AI 기반 추천/요약/오답 분석
- 집중 타이머와 활동 통계, 히트맵
- 커뮤니티 게시글, 댓글, 반응, 북마크, 신고
- 친구 요청, 공개 프로필, 실시간 쪽지
- 포인트, 상점, 프로필 꾸미기, 보상
- 협동 퀘스트와 보스 레이드
- 접근성 설정, 돋보기, 전체 읽기
- 관리자 점검 모드, 공지, 신고/계정 상태 관리

상세 요구사항과 추적성은 [요구사항 문서](../requirements/requirements-document.md)를 기준으로 한다.

## 4. 설계 요약

프론트엔드는 Expo/React Native Web 기반 화면 구성과 상태 관리를 담당한다. 백엔드는 Express 기반 REST API와 WebSocket 이벤트를 제공하며, Prisma를 통해 DB에 접근한다. 주요 API는 routes, controllers, services, repositories 계층으로 나누어 구현했다. 실시간 알림은 WebSocket을 사용하고, WebSocket 연결 실패 시 HTTP fallback을 유지한다.

설계 세부 내용은 [아키텍처 개요](../design/architecture-overview.md), [클래스 다이어그램](../design/class-diagram.md), [시퀀스 다이어그램](../design/sequence-diagram.md)에 정리되어 있다.

## 5. 기술 스택

| 영역 | 기술 | 선정 이유 |
|---|---|---|
| Frontend | Expo, React Native Web | 웹/모바일 공통 UI 구현과 빠른 화면 검증 |
| Backend | Node.js, Express | REST API와 WebSocket 서버를 단순한 구조로 구현 |
| Database | Prisma 기반 관계형 DB | 모델 중심 데이터 접근, schema 검증, migration 관리 |
| Test | Jest, Supertest | API 단위/통합 테스트와 repository mock 검증 |
| Deploy | Vercel, Render 계열 배포 구조 | 프론트와 백엔드 분리 배포 및 smoke test 수행 |

## 6. 핵심 구현 기능

### 6.1 인증과 계정 관리

회원가입, 로그인, 현재 사용자 조회, 비밀번호 변경, 회원 탈퇴, 계정 상태 제한을 구현했다. 정지 또는 비활성화 계정은 로그인 및 보호 API 접근을 제한하며, 관리자 변경 이벤트는 WebSocket으로 사용자에게 전달된다.

### 6.2 일정/칸반

학습 일정, D-Day, 칸반 태스크를 통해 오늘 해야 할 학습 계획을 정리한다. 대시보드에서는 주요 일정과 진행 중 퀘스트를 함께 확인할 수 있다.

### 6.3 AI 학습 기능

AI 질의, 추천, 요약, 오답 분석, AI 대화방 기능을 구현했다. 자동 테스트는 외부 AI API를 직접 호출하지 않고 provider mock과 fallback 중심으로 검증한다. 무료 API 한도와 key 관리 이슈가 있으므로, 실제 외부 AI 연동은 제한된 환경에서만 확인한다.

### 6.4 집중/통계

집중 세션 기록, 주간 통계, 히트맵 표시를 제공한다. 짧은 기록과 장시간 기록이 단계적으로 구분되도록 표시 강도를 조정했으며, 빈 데이터 상태도 별도로 처리한다.

### 6.5 커뮤니티

게시글 목록/상세, 댓글/대답글, 좋아요/싫어요, 북마크, 신고, 공개 프로필 이동 흐름을 구현했다. 상세 화면은 중앙 overlay 구조로 정리했고, 반응 수는 버튼 옆 숫자로 표시한다.

### 6.6 친구/쪽지

친구 검색, 친구 요청, 수락/거절, 친구 목록, 삭제 흐름을 구현했다. WebSocket 이벤트로 친구 요청 상태와 접속 상태를 갱신하고, 쪽지 thread와 읽음 상태를 실시간으로 반영한다.

### 6.7 보상/포인트 상점

학습 활동과 퀘스트 달성 보상, 포인트 상점, 프로필 꾸미기 아이템 구매/적용/해제 흐름을 구현했다. 적용된 칭호와 프로필 아이템은 마이페이지와 공개 프로필에서 같은 기준으로 표시한다.

### 6.8 레이드/협동 퀘스트

협동 퀘스트는 참여, 기여도, 진행률, 완료, 보상 수령, 사용자별 숨김/보관을 지원한다. 보스 레이드는 파티 생성, 공개 모집, 초대, 진행률, 보상 수령을 지원한다.

### 6.9 접근성

텍스트 크기, 고대비, 모션 감소, 초등학생 친화 UI, 돋보기, 전체 읽기, TTS/STT 및 복습 알림 흐름을 제공한다. 접근성 기능은 사용자의 학습 지속성을 높이기 위한 보조 기능으로 다룬다.

### 6.10 관리자/점검 모드

관리자는 사용자 계정 상태, 커뮤니티 신고, 보상 데이터, 점검 모드, 공지 이벤트를 관리할 수 있다. 점검 모드 중 일반 사용자는 안내 화면으로 이동하고, 관리자 계정은 관리 화면 접근 흐름을 유지한다.

## 7. 테스트와 CI/CD

최신 확인 기준으로 백엔드 Jest/Supertest 전체 테스트는 29 suites / 530 tests가 통과했다. `npm run check`는 backend test, Prisma validate, frontend config, Expo Web export를 포함한다. 배포 전에는 프론트 접근, API base URL, 인증, 주요 화면, WebSocket fallback, seed 데이터 표시 여부를 smoke test로 확인한다.

자세한 테스트 결과는 [테스트 보고서](../test-report/test-report.md)를 기준으로 한다.

## 8. 배포 구조

프론트엔드는 Expo Web export 결과를 Vercel에서 서비스하고, 백엔드는 별도 Node.js 서버로 REST API와 WebSocket을 제공한다. 프론트는 환경 변수로 백엔드 API base URL을 주입받는다. DB URL, JWT secret, API key 등 민감정보는 문서와 로그에 원문으로 남기지 않는다.

설치와 실행 방법은 [설치 및 사용 가이드](../deployment/install-and-usage-guide.md), 배포 확인 항목은 [Vercel smoke test](../deployment/vercel-smoke-test.md)에 정리되어 있다.

## 9. 한계점

- 무료 AI API 한도와 key 관리 이슈로 실제 외부 AI 호출은 제한적으로만 검증한다.
- 보스 레이드 참여자별 서버 저장형 숨김/탈퇴 정책은 schema와 보상/기여도 보존 정책 논의가 필요해 후속 Issue #389로 분리했다.
- 프론트엔드 자동 E2E 테스트와 정량 coverage 측정은 보강 여지가 남아 있다.
- 실제 운영 수준의 알림, 외부 캘린더 연동, 고급 AI 개인화는 향후 확장 범위로 남아 있다.

## 10. 향후 확장성

- AI 학습 추천의 장기 학습 이력 기반 개인화
- 외부 캘린더 연동과 알림 채널 확장
- 보스 레이드 참여자별 visibility와 중도 탈퇴 정책 설계
- 프론트 E2E 테스트와 접근성 자동 검증 확대
- 운영 배포 환경의 모니터링, 로깅, 장애 대응 체계 강화
