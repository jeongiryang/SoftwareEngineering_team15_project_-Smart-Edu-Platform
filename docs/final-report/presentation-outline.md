# 최종 발표자료 구성안

## 1. 문서 목적

이 문서는 소프트웨어공학 15조 `사각사각 Smart Edu Platform`의 최종 발표자료 구성과 최종 발표 영상 제작 계획을 정리한다. 발표는 PPT 설명과 데모 영상을 하나의 흐름으로 연결해, 문제 정의부터 실제 서비스 동작까지 의뢰자에게 결과물을 설명하는 방식으로 진행한다.

최종 제출 영상은 `황대겸 PPT 발표 영상 + 박지환 데모 영상`을 이어 붙여 제작한다. 박지환이 담당한 데모 영상은 완료된 상태로 보고, 황대겸 발표 영상이 준비되면 정이량이 두 영상을 병합, 편집, 자막, 썸네일, YouTube 비공개 업로드 흐름까지 관리한다.

## 2. 최종 발표 전체 구성

| 구분 | 시간 | 내용 |
|---|---:|---|
| PPT 발표 | 약 6분 | 문제 정의, 서비스 사용 흐름, 운영·접근성 범위, 요구사항 수행 현황, 테스트 점검 |
| 데모 영상 | 약 4분 | 실제 웹 서비스 주요 기능 시연 |
| 전체 흐름 | 약 10분 | PPT로 서비스 가치와 구현 범위를 설명한 뒤 데모 영상으로 실제 동작을 확인 |

발표 순서는 `PPT 설명 -> 데모 영상`으로 구성한다. PPT 마지막에는 `이어서 준비된 데모 영상으로 사각사각의 실제 동작을 보여드리겠습니다.`라는 흐름으로 자연스럽게 데모 영상으로 전환한다.

## 3. PPT 발표 흐름

### 3.1 표지와 서비스 한 줄 소개

- 제목: `사각사각 Smart Edu Platform`
- 팀: 사각사각팀
- 팀원: 황대겸, 정이량, 박지환
- 한 줄 소개: 학습 계획, AI 복습, 동기 부여, 운영 관리를 하나로 연결한 학습 관리 서비스

표지에서는 서비스가 단순 학습 도구가 아니라 학습 흐름 전체를 연결하는 플랫폼임을 먼저 제시한다.

### 3.2 목차

PPT 목차는 다음 다섯 흐름으로 정리한다.

1. 문제 정의
2. 서비스 사용 흐름
3. 운영·접근성 범위
4. 요구사항 수행 현황
5. 테스트 점검

이 목차는 요구사항 문서와 최종보고서의 전체 구조를 발표 시간에 맞게 압축한 형태이다.

### 3.3 문제 정의

문제 정의에서는 학습자가 겪는 불편과 운영자가 고려해야 할 부담을 함께 설명한다.

| 문제 | 발표 설명 방향 |
|---|---|
| 학습 도구 분산 | 일정, 노트, 질문, 타이머가 흩어져 학습 흐름이 끊기는 문제 |
| 참여 지속성 약화 | 학습 결과가 보상이나 관계로 이어지지 않아 장기 사용 동기가 약해지는 문제 |
| 운영·보안 부담 | 계정 관리, 신고 처리, 점검 안내, 데이터 보호를 함께 고려해야 하는 문제 |

요구사항은 다음 세 문장으로 요약해 전달한다.

- 학습 흐름을 하나로 이어주는 통합 학습 서비스
- 확실한 보상으로 계속 찾게 되는 동기부여 서비스
- 관리자와 유저 모두 안전하고 편리한 신뢰할 수 있는 서비스

### 3.4 서비스 사용 흐름

서비스 사용 흐름은 `계획하기 -> 집중하기 -> AI 복습 -> 함께하기 -> 관리하기` 순서로 설명한다.

- 계획하기: 오늘 학습, 일정, 할 일 보드
- 집중하기: 스톱워치/타이머, 집중 기록, 통계, 히트맵
- AI 복습: 질문 응답, 오답·추천, 요약 분석, 퀴즈 초안
- 함께하기: 커뮤니티, 친구, 쪽지, 보상 상점, 협동 퀘스트
- 관리하기: 관리자 권한, 신고·제재, 점검 모드, 데이터 보호

발표에서는 계획, 집중, AI 피드백, 소통이 끊기지 않고 이어지는 점을 중심으로 설명한다.

### 3.5 첫 사용 흐름과 사용자 유형별 진입 이유

첫 사용 흐름은 `서비스 소개 -> 계정/프로필 -> 오늘 학습 진입`으로 정리한다.

| 사용자 유형 | 진입 이유 | 발표 설명 방향 |
|---|---|---|
| 초등학생 | 흥미와 보상 | 쉬운 표현, 보상, 상점, 협동 요소 |
| 수험생 | 계획과 집중 | 일정, D-Day, 칸반, 집중 기록 |
| 직장인 | 짧은 학습 | 요약, AI 복습, 빠른 학습 기록 |
| 시니어 | 접근성 | 큰 글씨, 고대비, 읽기 보조, 도움말 |
| 운영자 | 관리 가능성 | 신고 처리, 계정 상태, 점검 모드 |

PPT에서는 사용자 유형별 자동 화면 구성은 완전 자동화된 기능으로 과장하지 않고, 현재 구현된 기능을 사용자가 선택해 활용할 수 있다는 방향으로 설명한다.

### 3.6 학습 관리와 AI 복습 흐름

학습 관리 흐름은 다음 화면을 중심으로 설명한다.

- 오늘 학습 화면: 오늘 일정, 진행 상황, 학습 진입
- 일정·할 일 보드: 일정 관리, 알림 시간, 칸반 상태 변경
- 집중 기록: 타이머/스톱워치, 통계, 히트맵

AI 학습 지원 범위는 실제 구현된 기능을 기준으로 정리한다.

- 질문 응답
- 맞춤 학습 추천
- 긴 글 요약
- 오답 원인 분석
- 텍스트 기반 PDF 추출 후 요약·노트·퀴즈·키워드 초안 생성
- AI quota 또는 provider 오류 시 사용자용 fallback 안내

이미지 첨부 도구는 이미지 파일의 형식, 용량, 메타데이터를 검토하는 범위로 설명한다. 이미지 OCR, AI Vision 분석, 스캔 PDF OCR은 지원 범위가 아님을 명확히 한다.

### 3.7 학습 지속성과 동기부여

학습 지속성은 학습 결과가 관계와 보상으로 이어지는 구조로 설명한다.

- 커뮤니티: 게시글, 댓글, 반응, 북마크, 신고, 공유 popup
- 친구·쪽지: 친구 요청, 쪽지, 실시간 반영
- 포인트 상점: 포인트 사용, 칭호, 프로필 꾸미기
- 협동 퀘스트: 참여, 기여도, 진행 중 나가기, 보관
- 보스 레이드: 파티, 기여도, 보상, 숨김/보관/복원/나가기 정책

발표에서는 기능을 나열하기보다, 학습 행동이 기록과 보상으로 돌아와 다시 학습을 유도한다는 구조를 강조한다.

### 3.8 운영·접근성 범위

운영과 접근성은 섞이지 않게 두 축으로 나누어 설명한다.

| 축 | 발표 내용 |
|---|---|
| 접근성 | 큰 글씨, 고대비, 읽기 보조, 돋보기, 전체 읽기, 도움말 투어 |
| 운영 | 관리자 권한 분리, 신고·제재 처리, 계정 상태 변경, 점검 모드 |
| 보안 | JWT 기반 인증, bcrypt 비밀번호 해시, 사용자별 데이터 접근 제한 |

PPT에서 점검 모드와 데이터 보호 설명이 한 화면에 함께 보이더라도, 발표에서는 `운영 관리`와 `데이터 보호`를 분리해 말한다.

### 3.9 요구사항 수행 현황

요구사항 수행 현황은 필수 요구사항, 확장 구현, 후속 고도화 항목으로 구분해 설명한다.

| 구분 | 발표 설명 방향 |
|---|---|
| 계정·프로필·보안 | 회원가입, 로그인, 계정 상태, 비밀번호 해시, 프로필/칭호 |
| 일정·할 일·집중·통계 | 일정, 알림 시간, 칸반, 타이머/스톱워치, 통계, 히트맵 |
| 노트·AI·요약·퀴즈 초안 | AI 질문, 추천, 요약, 오답 분석, 텍스트 기반 PDF 분석 |
| 커뮤니티·보상·협동 | 커뮤니티, 친구/쪽지, 포인트 상점, 협동 퀘스트, 보스 레이드 |
| 접근성·전연령 화면 | 큰 글씨, 고대비, 돋보기, 전체 읽기, 도움말 |
| 후속 고도화 | 외부 캘린더 연동, 장기 운영 모니터링, frontend E2E/정량 coverage |

보스 레이드 참여자별 숨김/탈퇴 정책은 후속 설계가 아니라 구현 완료 범위로 설명한다. 서버 저장형 `hiddenAt`, `archivedAt`, `leftAt` 기반 정책과 기여도/보상 기록 보존을 반영했다.

### 3.10 테스트와 점검

테스트 점검은 다음 근거를 중심으로 설명한다.

| 점검 항목 | 발표 내용 |
|---|---|
| 문서 연결 | 요구사항, 설계, API, 테스트 보고서, 최종보고서 연결 |
| API 테스트 | Backend API `29 suites / 548 tests` 통과 |
| coverage | backend coverage 약 68.6% |
| AI 확인 | quota/fallback, 안전한 오류 안내, 실제 지원 범위 정리 |
| 실행 확인 | Prisma validate/generate, Expo Web export 통과 |
| 화면 점검 | 주요 화면 직접 확인, 배포 smoke test 문서화 |

발표에서는 미해결 기능 버그가 문서에 남아 있지 않으며, 환경 주의사항은 별도 문서와 제출 설명에 기록했다고 설명한다.

### 3.11 마무리와 데모 영상 연결 멘트

마무리 슬라이드는 다음 메시지로 정리한다.

- 사각사각은 학습 흐름을 끊기지 않게 만드는 운영 가능한 학습 관리 서비스이다.
- 사용자 가치: 계획, 집중, AI 복습, 소통, 보상을 하나의 흐름으로 연결한다.
- 운영 가치: 관리자, 신고·제재, 점검, 보안 기준을 갖춘다.
- 검증 가치: 테스트, 문서, 배포 확인으로 구현 상태를 확인했다.

마지막 멘트는 데모 영상으로 자연스럽게 이어지도록 구성한다.

> 이어서 준비된 데모 영상으로 사각사각의 실제 동작을 보여드리겠습니다.

## 4. 데모 영상 구성 방향

데모 영상은 약 4분 내외로 구성한다. 박지환이 담당한 데모 영상은 이미 완료된 상태이며, 최종 영상에서는 PPT 발표 뒤에 이어 붙여 실제 서비스 동작을 보여준다.

데모는 단순 기능 나열이 아니라, 실제 사용자가 서비스를 사용하는 흐름처럼 구성한다.

1. 랜딩/서비스 소개
2. 로그인 또는 회원가입 흐름
3. 대시보드 진입
4. 오늘 학습, 일정, 칸반 확인
5. 집중 타이머와 통계/히트맵 확인
6. AI 학습 지원
   - 질문 응답
   - 요약/복습/퀴즈 초안
   - fallback 또는 한도 안내
7. 커뮤니티
   - 게시글 목록
   - 상세 overlay
   - 댓글/반응/북마크 흐름
8. 친구/쪽지
9. 포인트 상점/칭호/보상
10. 협동 퀘스트
11. 보스 레이드
12. 접근성 기능
    - 돋보기
    - 전체 읽기
    - 도움말 투어
13. 관리자/점검 모드 또는 운영 기능 요약

Render 무료 플랜 특성상 최초 접속 시 서버 응답이 지연될 수 있으므로, 촬영 전 백엔드를 미리 깨워 둔다. 데모 영상에서 로딩이 길게 보일 경우 편집으로 불필요한 대기 구간을 줄인다. 다만 e캠퍼스 제출 설명란에는 최초 접속 지연 가능성을 별도로 안내한다.

## 5. 최종 영상 편집 계획

최종 YouTube 제출 영상은 다음 순서로 구성한다.

1. 황대겸 PPT 발표 영상
2. 장면전환 효과
3. 박지환 데모 영상
4. 아웃트로

정이량은 황대겸 발표 영상과 박지환 데모 영상을 전달받아 병합 및 최종 편집을 담당한다. 편집 시 다음 기준을 적용한다.

- 황대겸 발표 영상의 앞뒤 불필요한 구간을 컷 편집한다.
- 박지환 데모 영상의 앞뒤 불필요한 구간을 컷 편집한다.
- 발표 영상에서 데모 영상으로 넘어가는 구간에는 장면전환 효과를 삽입한다.
- 장면전환은 과하지 않게, 발표 영상에서 실제 서비스 시연으로 넘어가는 느낌이 나도록 구성한다.
- 필요 시 중간에 `이어서 실제 서비스 동작을 데모 영상으로 확인하겠습니다.`라는 전환 문구를 넣는다.
- 영상 말미에는 간단한 아웃트로를 추가한다.

아웃트로에는 다음 문구를 사용할 수 있다.

- 사각사각 Smart Edu Platform
- Software Engineering Team 15
- 감사합니다

최종 파일명 예시는 `SmartEduPlatform_FinalPresentation_20260619.mp4`로 정리한다.

## 6. 자막 계획

- PPT 발표 영상과 데모 영상에는 자막을 넣는 방향으로 정리한다.
- 자막은 PPT 화면이나 데모 화면의 핵심 UI를 가리지 않도록 위치, 폰트, 크기를 조절한다.
- 황대겸은 자막 포함 버전과 자막 없는 원본 버전을 모두 전달한다.
- 자막이 화면을 가리거나 싱크가 맞지 않으면 무자막 원본을 기준으로 정이량이 다시 편집할 수 있도록 한다.
- 데모 영상 자막은 기능 설명을 짧고 명확하게 넣는다.
- 발표 영상 자막은 발표자의 말을 보조하되, 슬라이드 본문과 겹치지 않도록 한다.

## 7. 썸네일 계획

YouTube 비공개 업로드용 썸네일을 제작한다. 썸네일은 단순 화면 캡처가 아니라 프로젝트명과 서비스 성격이 보이도록 구성한다.

썸네일 문구 예시는 다음과 같다.

- 사각사각 Smart Edu Platform
- AI 기반 개인화 학습 관리 서비스
- Software Engineering Team 15

썸네일 톤은 발표자료와 맞춰 깔끔하게 구성한다.

## 8. YouTube 및 제출 계획

- YouTube 업로드는 비공개로 진행한다.
- 업로드 후 링크를 e캠퍼스 제출에 사용한다.
- 공동작업자를 초대한다.
- 제출물에는 secret, env, DB URL, token 원문을 포함하지 않는다.

e캠퍼스 제출 설명란에는 다음 항목을 포함한다.

| 항목 | 내용 |
|---|---|
| 배포 URL | 실제 서비스 접속 링크 |
| GitHub Repository | 최종 소스 코드와 PR/commit history |
| YouTube 발표 영상 | 비공개 발표 영상 링크 |
| 접속 안내 | Render 무료 플랜 특성상 최초 접속 시 서버 로딩이 다소 오래 걸릴 수 있음 |

최종 마감 목표는 2026년 6월 19일 17:00~18:00 사이로 정리한다.

## 9. 발표 자료와 데모 영상의 연결 방식

PPT 발표는 먼저 문제 정의와 서비스 가치를 설명하고, 데모 영상은 실제 기능이 그 흐름을 어떻게 구현했는지 보여준다. 따라서 발표자료와 데모 영상은 별도 산출물이 아니라 하나의 최종 발표 흐름으로 연결된다.

| 발표자료에서 설명한 가치 | 데모 영상에서 확인할 기능 |
|---|---|
| 학습 흐름 통합 | 랜딩, 대시보드, 일정, 칸반, 집중 타이머 |
| AI 복습 | 질문 응답, 요약, 퀴즈 초안, fallback 안내 |
| 참여 지속성 | 커뮤니티, 친구/쪽지, 포인트 상점, 협동 퀘스트 |
| 운영 가능성 | 관리자, 신고·제재, 점검 모드 |
| 접근성 | 큰 글씨, 고대비, 돋보기, 전체 읽기, 도움말 |
