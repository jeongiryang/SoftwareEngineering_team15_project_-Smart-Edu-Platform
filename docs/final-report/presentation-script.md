# 사각사각 최종 발표 대본

## 슬라이드 1. 표지 — 14초

안녕하세요.

사각사각팀에서 홍보 및 개발을 맡은 황대겸입니다.

## 슬라이드 2. 목차 — 20초

[클릭 1 — 01 서비스 의뢰 사항 표시]

먼저, **서비스 의뢰 사항**을 바탕으로 요구사항을 도출한 과정을 설명드리겠습니다.

[클릭 2 — 02 서비스 사용 흐름 표시]

이어서 **서비스 사용 흐름**을 통해 첫 사용부터 학습 관리, AI 복습과 지속 참여까지 살펴보겠습니다.

[클릭 3 — 03 운영·접근성 범위 표시]

다음으로 **운영·접근성 범위**에서 전 연령층 사용성과 관리자 운영 기능을 확인하겠습니다.

[클릭 4 — 04 요구사항 수행 현황 표시]

그다음 **요구사항 수행 현황**에서 주요 항목의 달성 상태와 검증 방법을 보여드리겠습니다.

[클릭 5 — 05 테스트 점검 표시]

마지막으로 **테스트 점검**을 통해 자동 테스트와 실제 서비스 실행 결과를 말씀드리겠습니다.

## 슬라이드 3. 서비스 의뢰 사항 — 23초

일정, 노트, 질문, 커뮤니티와 타이머가 흩어진 **학습 도구 분산**, 학습 결과와 보상의 연결이 약한 **참여 지속성 약화**, 계정, 신고, 권한과 민감정보 보호가 필요한 **운영·보안 부담**입니다.

[클릭 1 — 하단 요구사항 요약 표시]

## 슬라이드 4. 끊기지 않는 학습 흐름 — 23초

이러한 요구사항을 바탕으로 학습의 전 과정을 하나로 연결했습니다.

오른쪽 설명처럼 분리된 기능을 **계획, 집중, AI 피드백, 소통**으로 연결해 학습에 몰입할 수 있는 환경을 만들었습니다.

## 슬라이드 5. 첫 사용 흐름 — 17초

이제 사용자가 처음 서비스를 이용하는 흐름을 보겠습니다.

왼쪽 **서비스 소개**에서 목적을 이해하고, 가운데 **계정·프로필**로 개인 학습 흐름을 유지한 뒤, 오른쪽 **오늘 학습**에서 일정과 할 일로 바로 진입합니다.

[클릭 1 — 하단 첫 사용 흐름 요약 표시]

## 슬라이드 6. 사용자 유형별 진입 이유 — 27초

초등학생은 퀘스트·배지·쉬운 버튼을 통한 **흥미·보상**, 수험생은 D-Day·할 일 보드·집중 기록을 통한 **계획·집중**이 중심입니다.

직장인은 요약·저장 질문·자투리 시간 복습의 **짧은 학습**, 시니어는 큰 글씨·고대비·읽기 보조의 **접근성**, 운영자는 신고 처리·계정 제재·점검 안내의 **관리 가능성**이 중요합니다.

[클릭 1 — 하단 서비스 설계 기준 표시]

## 슬라이드 7. 학습 관리 흐름 — 17초

서비스에 진입한 뒤에는 계획이 실제 학습으로 이어집니다.

왼쪽 **오늘 학습 화면**은 일정과 학습 현황을 한곳에 모으고, 가운데 **일정·할 일 보드**는 계획을 실행 가능한 카드로 관리합니다.

오른쪽 **집중 기록**은 스톱워치와 타이머로 측정한 공부 시간을 데이터로 보여줍니다.

## 슬라이드 8. AI 복습 — 25초

학습을 실행한 다음에는 AI를 통해 복습으로 연결합니다.

오른쪽의 **질문 응답**은 내용 설명, **오답·추천**은 추가 학습 영역과 복습 카드 연결, **요약 분석**은 핵심 문장 정리, **퀴즈 초안**은 노트 기반 기초 문제 생성을 뜻합니다.

마지막 **안전한 처리**는 백엔드 API를 거쳐 요청을 처리하고, AI 응답 오류 시 폴백이라는 대체 안내를 제공하는 기능입니다.

## 슬라이드 9. 학습 지속성 — 21초

AI 복습 이후에는 관계와 보상으로 학습을 이어갈 이유를 제공합니다.

**커뮤니티**는 질문과 경험 공유, **친구·쪽지**는 접속 상태 확인과 실시간 채팅, **보상 상점**은 공부 결과를 포인트 사용처로 연결하는 기능입니다.

**협동 퀘스트**에서는 같은 목표를 친구와 함께 달성합니다.

## 슬라이드 10. 전 연령층을 위한 접근성 — 33초

왼쪽 **화면 보기 설정**에서는 글자 크기를 1배에서 2배까지 조절하고, 돋보기 모드로 UI를 확대합니다.

고대비, 초등학생 친화 UI, 읽어주기와 음성 입력을 켜고 끌 수 있으며, 읽어주기 목소리도 선택할 수 있습니다.

오른쪽 대응 포인트에서 초등학생은 아이콘 화면과 보상 피드백, 수험생은 D-Day·칸반·집중 기록·AI 오답 분석을 이용합니다.

직장인은 요약과 짧은 카드로 자투리 시간을 활용하고, 시니어는 큰 글씨·고대비·읽기 보조·도움말로 사용 장벽을 낮춥니다.

## 슬라이드 11. 운영과 보안 — 30초

사용자 편의뿐 아니라 실제 서비스의 운영과 보안도 고려했습니다.

예상 종료 시간이 미정임을 알리고, 사용자는 다시 확인하며 관리자는 별도로 로그인합니다.

오른쪽의 **관리자 권한 분리**는 사용자와 관리자 접근 영역을 나눕니다.

**신고·제재 처리**는 악성 게시글·댓글 삭제와 불량 사용자 제재, **점검 모드**는 업데이트 전용 안내 페이지를 뜻합니다.

마지막 **데이터 보호**에는 JWT 인증과 비밀번호는 비크립트를 이용해 안전한 해시 형태로 저장했습니다.

## 슬라이드 12. 요구사항 수행 현황 — 46초

이제 앞에서 설명한 기능의 요구사항 수행 현황을 보겠습니다.

**계정·프로필·보안**의 기능적 요구사항 1번부터 2번과 비기능적 요구사항 2번부터 3번은 인증·프로필·관리자 검사까지 완료했습니다.

**일정·할 일·집중·통계**의 기능적 요구사항 3번부터 5번과 15번부터 17번은 관련 기능과 통계를 검사했습니다.

**노트·AI·요약·퀴즈 초안**의 기능적 요구사항 6번부터 10번과 19번은 노트 저장, AI 응답과 fallback을 확인했습니다.

**커뮤니티·보상·협동**의 기능적 요구사항 12번부터 13번, 24번, 27번부터 29번은 게시판·보상·관리자 기능을 검사했습니다.

**접근성·전 연령 화면**의 기능적 요구사항 18번, 20번부터 21번, 23번, 25번은 직접 사용과 Expo Web 내보내기로 점검했습니다.

마지막 **후속 고도화**의 기능적 요구사항 14번과 22번, 비기능적 요구사항 4번은 앱 차단, 외부 캘린더와 장기 가동률입니다.

## 슬라이드 13. 테스트와 점검 — 34초

상단의 **문서 연결**은 요구사항과 기능 연결, **API 테스트**는 Jest와 Supertest 검사, **AI 확인**은 mock과 fallback 예외 점검입니다.

**실행 확인**은 Prisma와 Expo Web으로 진행했고, **화면 점검**은 배포 화면을 직접 사용해 확인했습니다.

하단 결과에서 백엔드는 로그인, 일정, AI, 게시판, 보상과 관리자 기능을 포함한 29개 묶음, 총 **548개 테스트를 통과**했습니다.

코드 검사 범위는 **68.6퍼센트**이며, 프론트엔드는 **Web export를 통과**했습니다.

현재 기록된 **미해결 기능 오류는 없으며**, 환경 주의사항은 별도로 기록했습니다.

## 슬라이드 14. 결론 — 20초

지금까지의 결과를 정리하겠습니다.

이어서 데모 영상으로 사각사각의 실제 동작을 보여드리겠습니다.
