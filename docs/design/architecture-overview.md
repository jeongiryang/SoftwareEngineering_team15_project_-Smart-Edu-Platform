# [15조] Smart Edu Platform 시스템 아키텍처 명세서

## 1. 아키텍처 개요 (Architecture Overview)

### 1.1 설계 목적 및 배경
본 섹션은 **'Smart Edu Platform(개인화된 학습 관리 앱)'** 의 기능적 요구사항과 품질 속성을 만족하기 위한 시스템 아키텍처의 기본 구조와 설계 원칙을 정의합니다. 본 플랫폼은 초등학생부터 시니어층까지 전 연령대를 아우르는 폭넓은 사용자를 수용해야 하며, 각 페르소나의 학습 목적(내신, 수능, 취업, 자격증, 치매 예방 등)에 맞는 맞춤형 기능을 제공해야 합니다. 

### 1.2 아키텍처 기본 원칙
1. **동적 UI 대응성 :** 사용자의 페르소나 정보에 따라 시스템의 화면 구성 요소와 테마가 유연하게 변경될 수 있도록 프론트엔드 컴포넌트를 모듈화합니다.
2. **비동기 자원 관리 :** 대형 언어 모델(LLM) 연동과 같이 대기 시간이 발생하는 외부 API 통신 시, 클라이언트의 사용자 경험(UX)이 중단되지 않도록 비동기 제어 흐름을 전 계층에 적용합니다.

## 2. 아키텍처 스타일 및 패턴 

소프트웨어 공학의 검증된 원칙에 의거하여, 본 플랫폼은 구현이 명확하고 유지보수가 용이한 복합 아키텍처 패턴을 채택합니다.

### 2.1 클라이언트-서버 아키텍처
시스템을 사용자 인터페이스를 전담하는 '모바일 클라이언트'와 비즈니스 로직 및 데이터를 처리하는 '백엔드 응용 서버'로 명확히 분리합니다.
* **Thin Client 전략:** 모바일 디바이스의 제한된 연산 자원과 배터리를 보호하기 위해, 크기가 큰 데이터의 가공, 통계 산출, 외부 AI API와의 통신 등 무거운 연산은 모두 백엔드 서버에서 처리하고 클라이언트는 렌더링과 사용자 입력 이벤트 처리에 집중합니다.

* **표준 RESTful API 통신:** 클라이언트와 서버는 HTTP/HTTPS 기반의 정형화된 REST API 인터페이스를 통해 소통합니다. 이를 통해 상호 간의 의존성을 줄이고, 향후 클라이언트를 확장할 때 백엔드 코드를 그대로 재사용할 수 있는 자원 독립성을 확보합니다.

### 2.2 단일 구조 계층형 아키텍처 
백엔드 서버 내부의 복잡도를 낮추고 소스코드의 응집도를 높이기 위해, 역할을 기준으로 3개의 논리적 계층(Layer)을 엄격히 분리합니다. 상위 계층은 인접한 하위 계층만 호출할 수 있도록 제한하여 코드의 가독성과 수정 용이성을 보장합니다.

1. **표현 계층 (Presentation Layer / Controller):**
   * 클라이언트의 HTTP 요청을 가장 먼저 받아들이는 진입점입니다. 
   * 입력 데이터의 유효성을 검증하고, 비즈니스 로직을 호출한 뒤, 그 결과를 규격화된 JSON 형태로 클라이언트에 반환합니다.
2. **비즈니스 로직 계층 (Business Logic Layer / Service):**
   * 플랫폼의 핵심 가치와 요구사항을 실현하는 계층입니다. 
   * 일정 관리 상태 변경, 순공 시간 누적 계산, AI 프롬프트 생성 가공 등 실제 도메인 규칙을 수행하는 순수 자바스크립트/타입스크립트 로직이 이 계층에 집중됩니다.
3. **데이터 접근 계층 (Data Access Layer / Repository):**
   * 데이터베이스와의 직접적인 데이터 입출력(CRUD)을 전담합니다. 
   * 상위 계층의 비즈니스 로직이 데이터베이스 시스템 종류(MySQL, SQLite 등)에 종속되지 않도록 추상화된 데이터 접근 인터페이스를 제공합니다.

### 2.3 프론트엔드 MVC (Model-View-Controller) 패턴
모바일 클라이언트(React Native) 내부에서 화면과 데이터를 분리 관리하기 위해 MVC 아키텍처 구조를 적용합니다.
* **Model (상태 데이터):** 현재 로그인한 사용자의 페르소나 타입, 오늘의 스톱워치 측정 시간, 칸반 보드 일정 목록 등 전역/로컬 상태 데이터를 관리합니다.
* **View (UI 컴포넌트):** 사용자에게 보여지는 화면입니다. 자체적인 비즈니스 로직을 가지지 않으며, Model의 데이터 변화를 감시하여 화면을 동적으로 그려냅니다. 페르소나 변수에 따라 '시니어 전용 큰 글씨 테마'나 '초등학생용 게이미피케이션 UI'로 분기되어 표현됩니다.
* **Controller (이벤트 핸들러):** 사용자의 버튼 터치, 입력 폼 제출 등의 이벤트를 받아 Model의 데이터를 변경하거나 백엔드 서버에 API 요청을 보내는 제어 역할을 담당합니다.

## 3. 시스템 논리 구조 및 서브시스템 분할

### 3.1 3-Tier 물리적 구조 정의
본 플랫폼은 개발 인프라 구축 비용을 최소화하고 안정적인 운영을 위해 가장 대중적이고 표준적인 3티어(3-Tier) 구성을 가집니다.

1. **Client Tier:** 자바스크립트 프로그래밍 기술을 활용하여 하나의 소스코드로 안드로이드와 iOS 앱을 동시에 빌드할 수 있는 React Native 프레임워크 기반의 모바일 어플리케이션입니다.
2. **Application Server Tier:**  Node.js 환경의 Express 웹 프레임워크를 사용합니다. 단일 웹 서버 프로세스 내에서 모든 비즈니스 도메인을 처리하는 효율적인 모놀리식 구조입니다.
3. **Database Tier:** 정형화된 관계형 데이터 모델을 안정적으로 지원하는 MySQL(@@데베 바꿔도 됨 ex)MongoDB@@)을 중앙 집중형 데이터 저장소로 채택합니다. 설치가 간편하고 클라우드(Supabase, AWS RDS 등) 연동이 쉬워 데이터 관리가 직관적입니다.

### 3.2 핵심 서브시스템(모듈) 분할 명세
요구사항 명세서의 기능적 요구사항(FR)을 기준으로 백엔드 서버의 도메인을 4개의 서브시스템 모듈로 분할하여 독립성을 확보합니다.

#### 3.2.1 사용자 및 페르소나 설정 모듈
* **주요 역할:** 회원가입, JWT(Json Web Token) 기반의 보안 로그인, 타겟 그룹별 맞춤 설정값 제어.

* **구현 전략:** 사용자가 로그인에 성공하면 서버는 암호화된 JWT 사원증 토큰과 함께 해당 유저의 페르소나 변수(예: SENIOR, EXAM_PREP 등)를 클라이언트에 넘겨줍니다. 클라이언트는 이 값을 로컬 상태에 저장하고 앱 전반의 테마(글자 크기, 색상, 메뉴 단순화 수준)를 결정하는 기준으로 사용합니다.

#### 3.2.2 AI 스마트 학습 모듈 
* **주요 역할:** 학습 노트 저장, OpenAI API 연동을 통한 퀴즈 추출 및 맞춤형 오답노트 구성.

* **구현 전략:** 사용자가 노트를 저장하면 서버는 해당 비정형 텍스트를 파싱하여 정교하게 설계된 프롬프트(Prompt)와 함께 OpenAI API로 전송합니다.  Node.js의 기본 비동기 구문을 활용하여 AI 결과가 반환될 때까지 안정적으로 대기한 뒤 결과를 MySQL DB에 일괄 저장합니다.

#### 3.2.3 일정 및 순공 시간 관리 모듈 
* **주요 역할:** 칸반 보드 형태의 태스크 상태 관리, D-Day 알림, 뽀모도로 타이머 시간 계산.

(@@이것도 구현 방법 서버측에서 실행되도록 할 수는 있을듯>?@@)
* **구현 전략:** 타이머의 실시간 초 단위 카운팅은 모바일 기기 자체(Client-side)에서 처리하도록 설계했습니다. 학습이 완전히 종료되는 시점에만 최종 측정된 '순공 시간(초 단위)'을 서버에 단 한 번의 REST API 요청으로 전송하여 DB의 누적 시간을 업데이트하는 방식으로 트래픽 부하를 원천 차단합니다.

#### 3.2.4 소셜 및 게이미피케이션 모듈 (Gamification Domain)
* **주요 역할:** 주간/월간 학습 시간 기반의 랭킹 리스트 출력, 뱃지 획득 조건 판별.
(@@웹소켓 기반 실시간 통신 서버 = 24시간 최신화 VS 데베에 요청 시 최신화 @@)
* **구현 전략:** 웹소켓 기반의 실시간 통신 서버를 따로 구축하는 대신, 사용자가 랭킹 탭이나 리포트 화면 진입을 위해 페이지를 요청할 때 데이터베이스에서 사용자들이 누적한 순공 시간을 ORDER BY 쿼리로 결합 정렬하여 응답하는 방식을 취합니다. 시스템 자원을 낭비하지 않으면서도 명확하게 요구사항을 실현합니다.

## 4. 비기능적 요구사항(NFR) 충족을 위한 아키텍처 전략

아키텍처 설계의 최종 목표는 비기능적 요구사항의 달성에 있습니다. 본 설계는 시스템 인프라를 단순화하면서도 아래의 품질 전략을 통해 앱의 안정성을 확보합니다.

### 4.1 성능 및 응답성 
* **Non-blocking I/O 활용:** 외부 AI 모델(OpenAI)과 통신할 때 발생하는 긴 대기 시간 동안 서버가 멈추는 것을 방지하기 위해, 백엔드 로직 전체에 자바스크립트의 `async/await` 구문을 적용합니다. 
* **사용자 경험 보호:** AI 연산이 처리되는 동안 클라이언트 앱 화면에서는 로딩 스피너(애니메이션)를 보여주어 화면이 멈춘 것이 아님을 인지시키고, 작업이 완료되면 화면 데이터가 자연스럽게 리프레시되도록 비동기 UX 환경을 구성합니다.

### 4.2 보안성 및 데이터 보호 (Security)
* **패스워드 보안:** 사용자의 비밀번호는 텍스트 그대로 저장하지 않으며, 전 세계 표준 보안 라이브러리인 `bcrypt`를 활용하여 단방향 해시 암호화 처리를 거친 후 데이터베이스에 적재합니다. 대화 유출 및 해킹을 방지하기 위해 모든 API 네트워크 통신은 기본적으로 HTTPS 프로토콜 체계에서 이루어지도록 제한합니다.
* **데이터 접근 제어:** 클라이언트가 데이터베이스에 임의로 접근하는 통로를 원천 차단하고, 오직 인증 필터(JWT Filter)를 통과한 검증된 사용자 요청만 비즈니스 레이어를 거쳐 데이터를 읽고 쓸 수 있도록 격리성을 강화합니다.

### 4.3 이식성 및 개발 효율성 (Portability & Efficiency)
* **크로스 플랫폼 아키텍처:** 프론트엔드를 안드로이드 전용 코드가 아닌 웹 표준 기반의 React Native 구조로 개발하여 단일 소스코드 제어를 실현합니다. 이로 인해 향후 플랫폼이 확장되더라도 최소한의 공수로 앱을 이식할 수 있는 유연성을 확보합니다.
