## 2. 주요 논의 내용

### 2.1 1단계 제출 전 최종 문서 검토

- 요구사항 문서와 설계 문서를 중심으로 1단계 제출 전 최종 검토를 진행함.
- 2026년 05월 22일 이후 회의 내용은 API 구현, DB 운영, 테스트, PR 검증 등 2단계 구현 관련성이 커서 1단계 제출 범위에서는 제외하는 방향으로 정리함.
- 설계 문서에는 과제에서 요구한 아키텍처, UML, 시퀀스 흐름, 이미지 자료가 포함되어 있음을 확인함.
- 요구사항 문서에는 잠재적 실사용자 관점뿐 아니라 서비스 의뢰자 및 이해관계자 페르소나도 본문에 반영하는 것이 문서 목적과 자연스럽게 맞는다는 의견이 있었음.
- 이에 따라 요구사항 문서에 공식 의뢰자, 서비스 기획자, 교육기관/학원 운영자, 학습 플랫폼 관리자, 데이터/보안 담당자, 에듀테크 사업 책임자 관점을 보강함.
- 1단계 제출 요소인 요구사항, 페르소나, 유스케이스, 기능/비기능 요구사항, 설계 문서, 다이어그램, AI 시뮬레이션 근거는 충분히 포함된 것으로 확인함.

### 2.2 부적절한 스터디 챌린지 기준 논의

- 스터디 챌린지는 일반 사용자가 생성할 수 있는 기능으로 가정함.
- 부적절한 스터디 챌린지의 예시는 다음과 같이 정리함.
  - 타인을 비난하거나 특정 사용자를 공격하는 챌린지
  - 불순한 목적이나 학습과 무관한 목적을 가진 챌린지
  - 허위 인증을 유도하거나 실제 학습 활동과 맞지 않는 챌린지
  - 학습 플랫폼의 취지와 맞지 않는 부적절한 목표를 포함한 챌린지
- 부적절한 챌린지는 관리자 판단에 따라 제재하거나 관리하는 방향으로 정리함.
- 해당 논의는 관리자 기능, 사용자 제재, 스터디 챌린지 관리 요구사항과 연결되는 후속 구현 판단 근거로 남김.

### 2.3 3단계 발표 및 데모 영상 방향

- 3단계에는 최종보고서, 발표자료, 데모 영상 제작이 포함되어 작업 부담이 크다는 점을 공유함.
- 발표를 한 명이 진행해도 되는지, 팀원 전체가 참여해야 하는지, 발표 인원 구성이 평가에 영향을 주는지 교수님께 확인하기로 함.
- 데모 영상은 단순 기능 나열보다 서비스 소개 영상처럼 자연스러운 흐름으로 구성하는 방향을 검토함.
- 다음 미팅에서 발표 방식, 데모 영상 형식, 역할 분담을 추가로 확인하기로 함.

### 2.4 남은 구현 일정과 역할 분담

- 1단계 제출 이후 다음 주 일요일까지 남은 구현을 최대한 마무리하고 시험 기간에 대비하는 방향으로 목표를 잡음.
- 박지환은 기존 담당 작업인 학습 일정/칸반 프론트 연결과 집중 시간/통계 API 작업을 계속 진행하기로 함.
- 정이량은 박지환 담당 범위를 제외한 남은 기능 구현과 조원 PR 검토/관리 역할을 이어가기로 함.
- 황대겸은 UI/UX 및 CSS 개선 작업을 맡아 웹 기준 화면부터 개선 방향을 잡기로 함.

### 2.5 UI/UX 및 CSS 개선 방향

- 우선 웹 화면 기준으로 현재 구현된 화면의 레이아웃과 디자인을 개선하기로 함.
- 백엔드 API와 계층 구조는 건드리지 않고 프론트 화면, 레이아웃, 스타일 중심으로 작업하기로 함.
- 하단 탭 또는 주요 페이지 이동 구조를 현대적인 앱 스타일에 맞게 검토하기로 함.
- 특정 앱 디자인을 그대로 복사하지 않고, 참고 자료를 바탕으로 Smart Edu Platform에 맞는 UI 톤으로 재설계하기로 함.
- 추후 팀원들이 함께 모여 최종 UI/UX를 점검하기로 함.

### 2.6 커뮤니티 기존 레포 참고 방향

- 기존 커뮤니티 레포는 기본 커뮤니티 기능 흐름과 정보 구조를 참고하는 용도로만 사용하기로 함.
- 기존 코드를 그대로 복사하지 않고, Smart Edu Platform의 백엔드 계층 구조와 문서 기준에 맞게 API와 로직을 재설계하기로 함.
- 커뮤니티 API와 로직을 처음부터 설계하는 부담을 줄이기 위해 기존 레포의 게시글, 댓글, 반응, 검색, 정렬, 페이징 흐름을 참고하기로 함.
- 기존 static HTML/CSS/Vanilla JS UI는 그대로 가져오지 않고, Smart Edu의 Expo React Native/Web 구조에 맞게 새로 설계하기로 함.
