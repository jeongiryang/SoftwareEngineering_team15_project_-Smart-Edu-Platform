## 2. 논의 내용

### 2.1 소개페이지 인트로 및 서비스 소개 PR #264 검토

- 팀원이 작성한 PR #264는 소개페이지 인트로 영상과 스크롤 반응 개선 방향을 제시한 PR로 확인했다.
- 제안된 방향 자체는 긍정적으로 평가했으나, 최신 main과의 충돌 가능성, 변경 파일 범위, PR 본문, 첨부 이미지와 동작 결과를 비판적으로 검토해야 한다고 판단했다.
- PR #264를 그대로 병합하지 않고, 의도와 구조를 인수인계한 뒤 최신 main 기준으로 재구현하고 보완하는 흐름이 더 안전하다고 정리했다.
- 인트로는 단순한 진입 영상이나 장식 효과가 아니라, 서비스의 첫인상과 브랜드 방향을 보여주는 고리로 발전시켜야 한다고 논의했다.
- 서비스 소개 영역은 실제 구현 기능과 일치해야 하며, 카드 구성과 스크롤 인터랙션도 최신 main의 기능 흐름을 기준으로 정리하기로 했다.

### 2.2 인트로 구현 난이도와 역할 분담

- 인트로 구현은 시각 연출, 반응형 확인, 브라우저 렌더링 QA가 함께 필요한 작업으로 확인했다.
- 팀원이 작성한 PR #264는 기초 방향과 구조 제안으로 활용하고, 이후 최신 main에 맞춘 재구현과 검증은 Codex를 활용해 단계적으로 보완하는 방식으로 정리했다.
- 논의 과정에서 특정 작업자의 결과를 비판하는 표현은 회의록에 남기지 않고, 초기 방향 제안, 문제 확인, 최신 main 기준 보완 필요성 중심으로 기록하기로 했다.
- 인트로는 화면 전체를 사용하는 입자 수렴 연출과 서비스 브랜드 텍스트 형성 흐름을 기준으로 QA해야 한다고 정리했다.

### 2.3 서비스 소개 화면 방향

- PR #264의 서비스 소개 카드 배치와 섹션 흐름은 참고할 가치가 있다고 판단했다.
- 다만 현재 구현 기능과 맞지 않거나 최신 main에 맞지 않는 문구와 구조는 보완해야 한다고 정리했다.
- 서비스 소개는 AI 학습, 일정/칸반, 집중 시간/통계, 커뮤니티, 친구/쪽지, 협동 퀘스트, 보상, 접근성처럼 실제 구현 기능을 기준으로 설명해야 한다.
- 정적 구조를 안정화한 뒤 카드 내부 마이크로 애니메이션, 다국어 문구 보강, 반응형 QA를 단계적으로 적용하는 방향으로 정리했다.

### 2.4 6월 1일 기준 후속 개선 목록

- 타이머 마우스 조작 중 전체 화면이 함께 스크롤되는 문제를 점검하기로 했다.
- 타이머에 진행률 그래프를 추가하는 방향을 검토하기로 했다.
- 스톱워치와 타이머 일시정지 기능을 점검하기로 했다.
- 친구창이 화면 밖으로 밀려 보이는 문제를 확인하기로 했다.
- 모바일 viewport 기준 전체 화면 최적화를 진행하기로 했다.
- 쪽지 보내기에서 Enter 입력 지원 여부를 확인하기로 했다.
- 쪽지 화면에서 친구 프로필로 접근하는 흐름을 점검하기로 했다.
- 커뮤니티 표보기 화면에서 레이아웃이 짤리는 문제를 확인하기로 했다.
- 포인트 상점과 친구 화면에서 공개 프로필 접근 및 쪽지 버튼 흐름을 개선하기로 했다.
- 대시보드 일부 섹션에서 부적절한 학습 완료 문구가 남아 있는지 확인하기로 했다.
- 라이트 모드 아이콘을 해 모양으로 바꾸는 방향을 검토하기로 했다.
- 타이핑 UI 효과를 지우개보다 연필 필기 느낌에 가깝게 개선하는 방향을 검토하기로 했다.
- PR #264는 직접 병합하지 않고, 최신 main 기준으로 필요한 의도를 인수인계하여 보완하는 방향으로 처리하기로 했다.

### 2.5 발표자료와 최종 산출물 준비 방향

- 발표자료에는 기능 목록뿐 아니라 작업 방식, 작업 흐름, 요구사항 문서와 설계 문서의 연결성을 함께 포함하기로 했다.
- 주제 선정 이유는 아이디어가 나오게 된 배경과 요구사항 도출 과정이 드러나도록 정리하기로 했다.
- 회의록은 날짜별로 체계화하고, 각 문서는 상위 개념과 하위 세부 항목이 분리되도록 구성하기로 했다.
- 요구사항은 서비스 사용자 관점과 관리자 관점을 분리해 설명하기로 했다.
- 설계 문서, 기술 스택 선정 이유, README 작업 규칙, AI 사용 규칙 문서도 발표자료에서 요약 설명할 수 있도록 정리하기로 했다.
- 핵심 기능은 교수자가 제시한 주제 요구사항의 필수 기능이 구현되었음을 중심으로 설명하고, 쪽지, 커뮤니티, 접근성, 협동/보상 기능은 확장 구현으로 구분하기로 했다.
- 최종 산출물에는 각 팀원의 작업에서 어려웠던 점, 성장한 점, 극복 과정, 협업 경험을 개인 회고 형태로 수집해 반영하기로 했다.

### 2.6 후속 작업 관리 방식

- 후속 작업은 Issue, branch, PR 단위로 분리해 처리하기로 했다.
- 기능 추가, UI 보정, 다국어 QA, 배포 smoke test, 발표자료 준비는 서로 다른 작업 단위로 관리하기로 했다.
- PR 본문에는 변경 파일, 검증 결과, 영향 범위, 관련 Issue를 명확히 적기로 했다.
- 문서 작업에는 `docs` label을 사용하고, `documentation` label은 사용하지 않기로 했다.
- seed와 migration은 회의록 또는 문서 작업 중 실행하지 않으며, 실제 실행이 필요한 경우 별도 승인과 DB 대상 확인을 거치기로 했다.

## 4. 후속 작업

- PR #264 superseded 처리 여부 최종 정리
- 소개페이지 인트로와 서비스 소개가 최신 main에 반영된 상태인지 확인
- 전체 화면 수동 QA 진행
- 다국어 QA 진행
- 배포 smoke test 진행
- 타이머 조작 중 전체 화면 스크롤 문제 확인
- 타이머 진행률 그래프 및 일시정지 기능 검토

- 쪽지 Enter 전송, 친구 프로필 접근, 읽지 않은 메시지 흐름 확인
- 커뮤니티 표보기 레이아웃 짤림 문제 확인
- 포인트 상점과 공개 프로필 연결 흐름 확인
- 대시보드의 부적절한 학습 완료 문구 제거 여부 확인
- 라이트 모드 아이콘과 타이핑 UI 효과 개선 검토
- 최종보고서 초안 작성
- 발표자료 구성안 작성
- 데모 영상 시나리오 작성
- 설치 및 사용 가이드 정리
