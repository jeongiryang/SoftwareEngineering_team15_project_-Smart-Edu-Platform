## 2. 주요 논의 내용

### 2.1 PR 리뷰 및 문서 검토 계획

정이량이 PR #24, PR #26 확인을 요청함. 박지환이 PR #24에 코멘트를 남겼으며, PR #26은 merge 완료 후 조원들에게 main 최신화를 요청함.

PR 리뷰 이후에는 요구사항 문서와 설계 문서의 최종 검토를 이어가기로 함.

### 2.2 docs/design, docs/requirements 최종 점검 계획

다음 오프라인 또는 대면 작업에서 `docs/design`, `docs/requirements` 하위 문서를 Markdown 미리보기 기준으로 함께 확인하기로 함.

검토 기준은 다음과 같이 정리함.

- 문서 흐름
- 표현과 문체
- 가독성
- 이미지 링크
- 내용 정합성

요구사항 문서와 설계 문서가 제출 가능한 형태인지 최종 확인하기로 함.

### 2.3 README와 개발 문서 분리 필요성

README가 협업 규칙, 실행 명령어, 테스트 방법, AI 에이전트 안전 규칙 등을 포함하면서 길어졌다는 의견이 나옴.

실행 명령어 요약과 로컬 개발 환경 세팅 방법은 별도 `docs` 문서로 분리하고, README에서는 링크로 참조하는 방향이 적절하다는 의견이 제시됨.

최종 단계에서는 README를 프로젝트 소개 중심으로 재구성하고, 개발/협업/배포/AI 안전 규칙은 별도 문서로 분리하는 방향을 검토하기로 함.

### 2.4 전체 클래스 다이어그램 이미지 잘림 현상

황대겸이 전체 클래스 다이어그램 이미지의 우측 일부가 잘린 현상을 발견함.

문제는 Markdown 링크 문제가 아니라 PNG 렌더링/export 결과 자체가 잘린 문제로 판단함.

전체 클래스 다이어그램 이미지 경로는 PR #27 이후 `screenshots/class-diagram/class-diagram.png` 기준으로 정리되어야 함을 확인함.

기존 경로인 `screenshots/class-diagram.png`는 현재 저장소 구조와 맞지 않으므로 Issue 내용 수정이 필요하다고 판단함.

### 2.5 Issue #28 생성 및 정리

전체 클래스 다이어그램 이미지 잘림 문제를 Issue #28로 정리함.

Issue #28에는 다음 내용을 명확히 적기로 함.

- 문제 목적
- 발생 배경
- 수정 대상
- 완료 기준
- 관련 파일

Issue 작성 시 이미지 첨부가 필요하면 GitHub Issue 본문에 직접 첨부할 수 있음을 확인함.

README/PR 문서에서는 이미지 경로 링크를 쓰는 것이 더 적절하지만, Issue에서는 첨부 이미지를 활용해도 된다고 정리함.

### 2.6 Issue 작성 방식 및 관리 규칙

앞으로 조원들도 직접 Issue를 생성하고 관리할 수 있도록 해야 한다는 의견이 나옴.

Issue 작성 시 Markdown 문법을 적용하고, 제목·목적·수정 범위·완료 기준을 명확히 작성하기로 함.

Issue 생성 시 label과 assignee를 함께 지정하는 방식을 공유함.

추후 2단계 구현 과정에서는 Issue 템플릿 또는 Issue 작성 규칙을 별도로 정리할 필요가 있다고 판단함.

### 2.7 전체/분할 클래스 다이어그램 정합성 후속 검토

전체 클래스 다이어그램의 잘림 현상을 수정한 뒤, 영역별 분할 클래스 다이어그램과의 정합성도 확인해야 한다는 의견이 나옴.

전체 클래스 다이어그램에는 여러 도메인이 존재하는데, 분할 이미지가 일부 도메인을 충분히 반영하지 않을 수 있음을 확인함.

전체 클래스 다이어그램과 분할 클래스 다이어그램의 클래스 구성, 도메인 수, 이미지 매핑을 다시 검토할 필요가 있다고 판단함.

이 내용은 이미지 잘림 수정과 별도 후속 작업으로 분리하여 진행하기로 함.
