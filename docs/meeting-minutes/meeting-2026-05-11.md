## 1. 구현 방향 논의

본 회의에서는 개인화된 학습 관리 앱의 주요 구현 범위와 요구 기능을 구체화함.

---

## 2. UI 구현 방향

### 2.1 접근성 중심 UI

- 큰 글씨 모드
- 고대비 모드
- 시니어 사용자를 고려한 단순한 화면 구성

### 2.2 초등학생 친화적 UI

- 아이콘 중심의 직관적인 화면
- 밝고 친근한 디자인
- 복잡한 텍스트보다 시각적 요소 중심의 구성

---

## 3. 사용자 요구 기능

### 3.1 커뮤니티 기능

- 주간 학습 랭킹
- 친구 간 스터디 공부 시간 채우기 챌린지
- 카테고리별 게시판
    - 질문 게시판
    - 자유 게시판
    - 학습 인증 게시판

### 3.2 AI 기능

- 질의를 통한 학습 지원
- 프롬프트 히스토리 기반 자동화 오답노트
- 사용자 성적 및 오답 기반 취약 과목 우선 추천

### 3.3 스케줄 관리 기능

- 칸반 보드 기반 To-do List
- 캘린더 기반 일정 관리
- 외부 캘린더 연동
- 마감일 알림

### 3.4 방해 금지 기능

- 앱 차단 모드
- 알림 끄기
- 무음/진동 전환

### 3.5 시간 관리 기능

- 스톱워치
- 타이머
- 마감 알림
- 순공 시간 기록

### 3.6 TTS 기능

- 텍스트 읽어주기
- 학습 내용 요약
- 출퇴근 및 이동 시간 학습 지원

## 4. 과제 주요 요구사항 반영

과제 안내에서 제시된 주요 요구사항을 다음과 같이 프로젝트 기능에 반영하기로 함.

| 과제 요구사항 | 프로젝트 반영 방향 |
|---|---|
| 사용자 등록/로그인 | 사용자 정보 저장, 회원가입, 로그인, 인증 기능 구현 |
| 학습 일정 관리 | 캘린더, 알림, To-do List, 마감일 관리 기능 구현 |
| 노트 및 퀴즈 생성/관리 | AI 기반 노트 작성, 퀴즈 생성, 오답노트 기능 구현 |
| AI 기반 학습 추천 | 사용자 성적 및 오답 기반 취약 과목 우선 추천 |
| 데이터 시각화 | 학습 진척도 그래프, 순공 시간 통계, 히트맵 제공 |
| 보안 및 프라이버시 | 비밀번호 암호화, 개인정보 보호, 권한 관리 |

## 6. 비기능적 요구사항 후보

| 구분 | 비기능적 요구사항 |
|---|---|
| 성능 | 사용자가 CRUD 기능을 수행했을 때 최소 응답 시간은 2초 이내여야 한다. |
| 보안 | 사용자 비밀번호는 암호화하여 저장해야 한다. |
| 보안 | 사용자 개인정보와 학습 데이터는 외부에 노출되지 않도록 보호해야 한다. |
| 가용성 | 시스템은 정기 점검 시간을 제외하고 99% 이상의 가동률을 목표로 한다. |
| 백업 및 복구 | 사용자 회원정보와 학습 데이터는 DBMS를 기반으로 관리하며, 장애 발생 시 복구할 수 있어야 한다. |
| 접근성 | 사용자는 큰 글씨 모드와 고대비 모드를 사용할 수 있어야 한다. |
| 권한 관리 | 시스템은 위치, 음악 및 오디오, 카메라, 캘린더, 파일 및 미디어 권한을 사용자 동의 후 요청해야 한다. |
| 유지보수성 | 서버 점검은 매주 수요일 00:00~01:30에 수행하며, 점검 중에는 점검 화면을 제공해야 한다. |
| 확장성 | 향후 새로운 학습 유형과 사용자 그룹을 추가할 수 있도록 기능을 모듈화해야 한다. |
