## 1. 다이어그램 작성 방식 논의

본 회의에서는 1단계 제출 문서에 포함할 다이어그램 작성 방식과 사용할 도구를 논의함.

요구사항 문서와 설계 문서에는 유스케이스 다이어그램, 클래스 다이어그램, 시퀀스 다이어그램, 시스템 아키텍처 다이어그램 등이 포함될 예정이므로, 각 다이어그램에 적합한 작성 도구를 검토함.

---

## 2. 다이어그램 작성 도구 검토

### 2.1 Mermaid

- Markdown 문서와의 연동이 쉬움
- GitHub, HackMD 등에서 코드 기반으로 다이어그램을 관리하기 편함
- 간단한 흐름도, 구조도, 관계도 작성에 적합함
- 다만 정통 UML 유스케이스 다이어그램 형태를 표현할 때 시각적 배치가 불편할 수 있음

### 2.2 PlantUML

- UML 다이어그램 작성에 적합함
- 유스케이스 다이어그램, 클래스 다이어그램, 시퀀스 다이어그램 작성에 유리함
- 액터, 시스템 경계, include/extend 관계 등을 명확하게 표현할 수 있음
- 코드 기반으로 작성할 수 있어 GitHub에서 변경 이력을 관리하기 좋음

---

## 3. 다이어그램 작성 도구 결정

회의 결과, 다이어그램 작성 도구는 **Mermaid와 PlantUML을 모두 사용해본 뒤 더 적합한 도구를 최종 선택**하기로 함.


따라서 현재 단계에서는 하나의 도구로 바로 확정하지 않고, 두 도구를 모두 사용해본 뒤 시각적 가독성, 작성 편의성, GitHub/HackMD 호환성, UML 표현 적합성을 기준으로 최종 도구를 결정하기로 함.

### 검토 기준

| 구분 | Mermaid | PlantUML |
|---|---|---|
| Markdown 연동 | 좋음 | 별도 렌더링 환경 필요 |
| GitHub/HackMD 활용 | 비교적 쉬움 | 환경에 따라 추가 설정 필요 |
| 유스케이스 다이어그램 표현 | 가능하나 배치가 불편할 수 있음 | UML 형식 표현에 적합 |
| 클래스 다이어그램 표현 | 가능 | 적합 |
| 시퀀스 다이어그램 표현 | 가능 | 적합 |
| 코드 기반 관리 | 가능 | 가능 |

### 결정 사항

| 항목 | 내용 |
|---|---|
| 최종 도구 | 아직 확정하지 않음 |
| 검토 방식 | Mermaid와 PlantUML을 각각 사용해본 뒤 비교 |
| 비교 기준 | 가독성, 작성 편의성, 문서 호환성, UML 표현력 |
| 현재 방향 | 유스케이스 다이어그램부터 두 방식으로 작성해보고 더 적합한 방식 선택 |

## 4. 요구사항 문서 작성 방향 논의

기존 요구사항 문서에는 프로젝트 개요, 주제 선정 배경, 향후 계획, 결론 등 보고서 성격의 내용이 많이 포함되어 있었다.

회의 결과, 요구사항 문서는 보고서 형식보다 **요구사항 명세 중심**으로 정리하는 것이 적절하다고 판단함.

### 정리 방향

- 프로젝트 개요는 짧게 유지
- 주제 선정 배경은 회의록 문서에서 관리
- 향후 계획과 결론은 요구사항 문서에서 제외하거나 최소화
- 사용자 요구사항, 기능 요구사항, 비기능 요구사항 중심으로 구성
- 요구사항 ID와 유스케이스 ID는 유지
- 이후 설계 문서와 테스트 보고서에서 요구사항 ID를 활용할 수 있도록 구성

---

## 5. 요구사항 ID 사용 결정

요구사항 문서에서 요구사항 ID를 사용할지 논의함.

회의 결과, 현재 단계에서는 ID 작성이 번거로울 수 있으나 이후 설계 문서, 테스트 보고서, 최종 보고서에서 요구사항을 추적하기 위해 ID를 유지하기로 결정함.

단, 기능 ID는 기능 요구사항 ID와 역할이 중복될 수 있으므로 문서 구조를 단순화하는 방향을 검토함.

### 결정 사항

| ID 유형 | 사용 목적 |
|---|---|
| UR | 사용자 요구사항 식별 |
| FR | 기능 요구사항 식별 |
| NFR | 비기능 요구사항 식별 |
| UC | 유스케이스 식별 |
| P | 페르소나 식별 |

### ID 유지 이유

- 설계 문서에서 요구사항과 기능을 연결하기 쉬움
- 테스트 보고서에서 테스트 케이스와 요구사항을 연결하기 쉬움
- 최종 보고서에서 기능 구현 근거를 설명하기 쉬움
- 요구사항 추적표 작성에 유리함
