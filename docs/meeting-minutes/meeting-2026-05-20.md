## 2. 교수님 미팅 주요 내용

### 2.1 문서 작성 범위 질의

조원이 1단계 문서를 어디까지 작성해야 하는지 모르겠다고 질문함.

교수님은 일반적으로 쓰이는 요구사항 문서와 설계 문서의 표준 구조를 따르는 것이 좋다고 답변함. 요구사항 문서에 설계 내용이 과하게 섞이면 이후 설계 단계와 충돌할 수 있으므로, 단계별 문서의 역할을 구분하는 것이 중요하다고 판단함.

현재 진행 중인 상위 문서, 하위 문서, 부록 구조는 문서화 방향으로 적절하다고 확인함.

### 2.2 문서화 수준과 근거 추적성

문서의 양은 적은 것보다 충분한 편이 좋으나, 불필요한 내용으로 채우는 것은 적절하지 않다고 판단함.

중요한 기준은 다음과 같음.

- 의사결정 근거를 추적 가능하게 남김
- 요구사항 도출 과정을 문서로 확인 가능하게 정리함
- 최종 결과물이 좋거나 나쁠 때도 왜 그런 결과가 나왔는지 문서로 유추할 수 있어야 함

### 2.3 고객 관점 확장 필요성

AI 인터뷰 시뮬레이션에서 서비스를 직접 사용하는 사용자뿐 아니라, 서비스를 만들어달라고 의뢰하는 고객 관점도 필요하다는 피드백이 나옴.

여기서 고객은 실제 서비스 사용자뿐 아니라, 개발팀에게 서비스를 의뢰하는 사람 또는 조직도 포함함.

따라서 요구사항 도출 근거를 보강할 때 다음 관점을 함께 반영하기로 함.

- 실제 서비스를 이용하는 잠재 사용자
- 서비스를 기획하거나 의뢰하는 공식 의뢰자
- 서비스 운영, 보안, 사업성을 검토하는 이해관계자

### 2.4 제출 일정 및 프로젝트 방향

1단계 요구사항 문서와 설계 문서는 다음 주 화요일까지 제출 예정임.

프로젝트가 끝난 뒤에도 완성도가 높으면 포트폴리오와 좋은 경험으로 이어질 수 있다는 의견이 공유됨. 따라서 문서와 산출물의 완성도를 높이는 방향으로 후속 작업을 진행하기로 함.

## 3. 조별 후속 논의 내용

### 3.1 공식 서비스 의뢰자 설정

공식 서비스 의뢰자는 1명으로 설정하기로 함.

공식 의뢰자는 **공공·평생교육기관 기반 디지털 학습 관리 플랫폼 시범사업 책임자**로 설정함.

“학습 플랫폼”보다 “학습 관리 플랫폼”이라는 표현이 현재 프로젝트 성격에 더 적절하다고 판단함.

### 3.2 이해관계자 관점 구성

이해관계자는 다음 5개 관점으로 정리함.

- 서비스 기획자
- 교육기관/학원 운영자
- 학습 플랫폼 관리자
- 데이터/보안 담당자
- 에듀테크 사업 책임자

각 이해관계자 관점은 4명 기준으로 구성하기로 함.

### 3.3 잠재 사용자 인터뷰 확장

잠재 사용자 인터뷰는 기존 7개 사용자 그룹을 유지하되, 각 그룹 15명으로 확장하기로 함.

유지할 사용자 그룹은 다음과 같음.

- 초등학생
- 중학생
- 고등학생
- 대학생/취준생
- 공시생/고시생
- 직장인
- 시니어 학습자

### 3.4 요구사항 범위 유지

의뢰자/이해관계자 인터뷰는 새 기능 추가가 아니라 기존 요구사항의 타당성, 우선순위, 운영성, 확장성, 보안성을 검토하는 근거로 활용하기로 함.

따라서 다음 산출물은 수정하지 않기로 함.

- 유스케이스 다이어그램
- 클래스 다이어그램
- 시퀀스 다이어그램
- DB/API 구조
- FR/NFR/UC 체계

### 3.5 부록 및 링크 구조 정리

부록 문서 목록은 링크 뒤 긴 설명을 줄이고, 파일/폴더 구조처럼 중첩 리스트로 정리하기로 함.

최종 문서 검토는 다음 기준으로 진행하기로 함.

- 표현
- 이미지 매핑
- 링크 연결
- 가독성
- 요구사항과 설계 문서 간 정합성

## 4. 결정 사항

- 공식 서비스 의뢰자는 1명으로 설정함.
- 공식 의뢰자는 공공·평생교육기관 기반 디지털 학습 관리 플랫폼 시범사업 책임자로 설정함.
- 잠재 사용자 인터뷰는 7개 그룹 × 15명 기준으로 확장함.
- 이해관계자 인터뷰는 5개 관점 × 4명 기준으로 구성함.
- 의뢰자/이해관계자 인터뷰는 기존 요구사항 검증 근거로만 활용함.
- 새 FR, 새 UC, 새 NFR은 추가하지 않음.
- 다이어그램, DB/API, 클래스/시퀀스 구조는 수정하지 않음.
- 부록 링크 목록은 Markdown 링크 중심의 중첩 리스트로 정리함.

## 5. 후속 작업

- 잠재 사용자 인터뷰 문서 파일명 및 성격 정리
- 잠재 사용자 인터뷰를 7개 그룹 × 15명 기준으로 확장
- 서비스 의뢰자 및 이해관계자 인터뷰 시뮬레이션 문서 추가
- 요구사항 문서에 고객 정의 확장 및 의뢰자 관점 반영
- AI 시뮬레이션 로그에 추가 인터뷰 과정 기록
- docs 하위 부록/관련 링크 목록 가독성 정리
