## 1. 1단계 산출물 작업 분담 논의

본 회의에서는 1단계 산출물인 요구사항 문서와 설계 문서를 이번 주 안에 완료하기 위해 작업 범위를 나누고, 조원별 담당 작업을 확정함.

1단계 산출물은 크게 다음 세 영역으로 나누어 진행하기로 함.

- 요구사항 문서
- 설계 문서 - 아키텍처 개요
- 설계 문서 - UML 다이어그램

---

## 2. 조원별 담당 작업

| 담당자 | 담당 문서/작업 | 세부 내용 |
|---|---|---|
| 정이량 | 요구사항 문서 / 유스케이스 | 요구사항 문서 최종 정리, 유스케이스 목록 및 유스케이스 다이어그램 작성 |
| 박지환 | 설계 문서 - 아키텍처 개요 | 시스템 아키텍처 개요 작성 |
| 황대겸 | 설계 문서 - UML | 클래스 다이어그램, 시퀀스 다이어그램 작성 |

---

## 3. 작업 기준 문서 결정

설계 문서와 UML 다이어그램은 현재 HackMD에 정리된 요구사항 문서를 기준으로 작성하기로 함.

요구사항 문서에 정의된 사용자 요구사항, 기능 요구사항, 비기능 요구사항, 유스케이스 목록을 설계 문서 작성의 기준 자료로 사용함.

---

## 4. 작업 마감 및 검토 일정

1단계 산출물은 내일까지 최종 확정하는 것을 목표로 함.

### 결정 사항

- 내일 저녁 7시까지 각자 맡은 작업을 최대한 마무리
- 작업 완료 후 조원 간 검토 진행
- 일정상 어려운 경우 가능한 범위까지 우선 진행
- 중간 결과물은 수시로 공유

## 5. GitHub 브랜치 작업 방식 결정

각 작업은 `main` 브랜치에서 직접 작업하지 않고, 작업별 브랜치를 생성한 뒤 Pull Request로 병합하기로 함.

처음에는 `docs/requirements/` 기준으로 논의했으나, 아키텍처 개요와 UML은 설계 문서에 해당하므로 `docs/design/` 경로에서 관리하기로 수정함.

## 7. Pull Request 규칙 확인

작업 완료 후 각자 Pull Request를 생성하기로 함.

### PR 작성 규칙

- 작업자는 본인을 담당자로 지정
- 리뷰어는 본인을 제외한 나머지 2명 추가
- README.md에 작성한 협업 규칙을 따름
- 브랜치명과 파일명은 작업 내용을 명확히 알 수 있도록 작성
- PR 생성 후 조원에게 확인 요청

---

## 8. 초기 환경 구축 및 파일 생성

1단계 설계 문서 작업을 빠르게 진행하기 위해, 정이량이 설계 문서 관련 브랜치와 기본 파일을 먼저 생성하기로 함.

### 생성 예정 항목

| 작업 구분 | 브랜치 | 파일 |
|---|---|---|
| 아키텍처 개요 | `docs/design-architecture` | `docs/design/architecture-overview.md` |
| UML 다이어그램 | `docs/design-uml` | `docs/design/class-diagram.md`, `docs/design/sequence-diagram.md` |

해당 브랜치와 파일을 미리 생성한 뒤 Pull Request를 열고, 각 담당자가 해당 브랜치에서 이어서 작업하기로 함.

## 9. 이미지 및 다이어그램 관리

다이어그램 이미지나 캡처 자료는 README.md에 작성한 기준에 맞춰 관리하기로 함.

- 문서용 이미지와 다이어그램은 `screenshots/` 폴더에서 관리
- 파일명은 어떤 자료인지 알 수 있게 명확하게 작성
- 유스케이스, 클래스, 시퀀스, 아키텍처 다이어그램 등은 이름만 보고 구분 가능하도록 작성

예시:

```text
usecase-diagram.png
class-diagram.png
sequence-diagram.png
architecture-overview.png
```
