## 2. 논의 내용

### 2.1 WebSocket 기반 실시간 기능 방향

- WebSocket 기반 실시간 기능을 구현 중인 상황을 공유함.
- WebSocket은 브라우저와 서버가 연결을 유지하고, 서버 상태 변경을 접속 중인 사용자 화면에 즉시 전달하는 구조로 정리함.
- 관리자 점검 모드 ON/OFF, 관리자 공지, 커뮤니티 알림, 친구 접속 상태, 보스 레이드 진행률, 협동 퀘스트 진행률을 WebSocket 기반 확장 후보로 보았음.
- Vercel은 frontend client 역할만 담당하고, 브라우저가 Render backend의 WebSocket endpoint에 접속하는 구조로 이해를 맞춤.

### 2.2 관리자 점검 모드와 실시간 반영

- 관리자 점검 모드 1차 구현이 main에 반영되었음을 공유함.
- 관리자는 점검 모드를 ON/OFF할 수 있고, 일반 사용자는 점검 화면을 보며, ADMIN 사용자는 우회 접근할 수 있다는 정책을 확인함.
- 1차 구현은 상태 조회 기반이므로 이미 접속 중인 사용자에게 즉시 반영하려면 WebSocket broadcast가 필요하다고 정리함.
- 점검 모드 기능은 단순 화면이 아니라 운영 중 긴급 안내나 업데이트 공지와 연결되는 관리자 운영 기능으로 보기로 함.

### 2.3 seed, migration, CI/CD 운영 기준

- seed는 로컬 또는 데모 DB에서만 수동 실행하는 기준을 유지하기로 함.
- production 또는 배포 DB에는 seed를 자동 실행하지 않는 원칙을 재확인함.
- schema 변경은 migration 파일과 함께 main에 반영되어야 하며, main 기준 CI/CD 흐름에서 migration이 자동 적용된다는 점을 공유함.
- 개인 로컬 DB는 자동 migration 대상이 아니므로 각자 필요 시 직접 migration을 적용해야 함.
- seed는 여러 번 실행할 경우 데이터 갱신 또는 초기화 영향이 있을 수 있으므로 실행 전 DB 대상을 반드시 확인해야 함.

### 2.4 버전 태그 및 GitHub Release 정리

- 핵심 구현 단위별로 SemVer tag와 GitHub Release를 정리한 내용을 공유함.
- `v1.0.0`부터 `v2.5.0`까지 기능 발전 흐름을 기록함.
- Release 본문은 한국어 기준으로 정리했고, 이후 말투도 간결한 보고체로 통일함.
- 버전 흐름은 MVP, 커뮤니티, 개인화 학습, 배포 자동화, 실시간 협동 기능, 계정 UX, 실시간 쪽지, 관리자 제재로 발전한 흐름을 설명하는 자료로 활용할 수 있음.

### 2.5 배포 사이트 실사용 테스트

- 배포된 Vercel 사이트를 팀에 공유하고 실제 사용자 관점으로 기능을 점검함.
- 회원가입, 로그인, 친구 추가, 쪽지, 관리자 공지, 계정 제재, 협동 퀘스트, 상점 등 주요 기능을 배포 환경에서 테스트함.
- 기능 구현 여부만 확인하는 단계에서 벗어나 실제 사용 중 불편한 지점, 어색한 UI, 다국어 누락, 반응형 문제를 제보하는 방식으로 QA를 진행하기로 함.
- 테스트 계정 사용 시 실제 개인정보나 중요한 비밀번호를 사용하지 않는 원칙을 유지함.

### 2.6 인증, 회원가입, 닉네임, 헤더 UX 개선

- 회원가입 화면의 음성 입력 버튼은 해당 맥락에서 사용성이 낮으므로 제거하기로 함.
- 비밀번호 안내 문구는 사용자가 이해하기 쉬운 방향으로 자연스럽게 수정하기로 함.
- 사용자 표시명 용어는 `이름`보다 `닉네임`으로 통일하는 것이 서비스 성격에 맞다고 판단함.
- 헤더의 `마이페이지` 텍스트 버튼은 아이콘 중심으로 정리하고, 대시보드의 중복 마이페이지 버튼은 제거하는 방향을 논의함.
- Language 선택과 라이트/다크 모드 전환은 설정 메뉴로 이동해 헤더를 간소화하기로 함.

### 2.7 실시간 쪽지 기능 테스트

- 친구 간 실시간 쪽지 기능을 구현하고 팀원 계정으로 실제 테스트함.
- 쪽지 내역이 DB에 저장되고, 로그아웃 후에도 기록이 유지되며, 다른 계정의 대화와 섞이지 않는 것을 확인함.
- 메시지 길이가 길어질 경우 화면이 아래로 밀리는 문제가 있어 쪽지 영역에 스크롤 처리가 필요하다고 정리함.
- 실시간 쪽지는 친구 기능을 단순 목록 관리에서 협업형 학습 기능의 기반으로 확장하는 요소로 보았음.

### 2.8 관리자 공지 및 계정 제재 UX

- 관리자 공지가 WebSocket으로 실시간 표시되는 것을 확인함.
- 기존 공지가 짧은 시간 뒤 사라지는 방식은 중요한 공지 전달에 부족할 수 있어, 사용자가 직접 닫기 전까지 유지되는 배너가 필요하다고 논의함.
- 관리자가 사용자를 정지 또는 비활성 처리했을 때 새로고침 후 로그아웃되는 현상을 확인함.
- 계정 제재는 접속 중인 사용자에게도 즉시 반영되어야 하며, 중앙 모달 또는 이용 제한 화면에 제재 사유가 표시되어야 한다고 정리함.
- 계정 상태 변경은 WebSocket event와 보호 API 차단을 함께 사용해야 운영상 더 안전하다고 판단함.

### 2.9 협동 퀘스트 및 보스 레이드 테스트

- 보스 레이드와 협동 퀘스트의 역할 차이를 정리함.
- 보스 레이드는 운영자 또는 관리자 중심의 이벤트형 협동 콘텐츠에 가깝고, 협동 퀘스트는 사용자가 목표를 만들고 함께 기여하는 사용자 주도형 협동 목표에 가깝다고 정리함.
- 협동 퀘스트 참여 방식과 기여도 입력 흐름을 테스트함.
- 기여 수치는 단순 숫자 입력보다 시간 또는 타이머 기반으로 서서히 증가하는 UX가 더 자연스러울 수 있어 후속 개선 후보로 남김.
- 기여도 입력 validation 문구가 영어로 표시되는 문제를 확인하고 다국어 QA 항목으로 분류함.

### 2.10 포인트 상점과 마이페이지 연동

- 상점에서 구매하거나 적용한 프로필 꾸미기 요소가 마이페이지에 실제로 반영되는지 점검함.
- 적용 결과가 마이페이지에 보이지 않는 경우 후속으로 수정하기로 함.
- 계정 상태는 활성, 정지, 비활성 등으로 구분되며, 관리자 운영 화면과 사용자 제한 화면에서 일관되게 표시되어야 함.

### 2.11 사용자 피드백 기반 QA 방식

- 팀원들이 실제 사용 중 발견한 문제를 메모 형태로 정리해 전달하기로 함.
- 버그인지 개선점인지 애매한 내용도 우선 기록하고, 이후 선별하여 Issue와 PR로 처리하기로 함.
- 레이드 테스트 데이터 부족, 협동 퀘스트 UX, 상점 적용 결과, 다국어 미적용, 쪽지 스크롤 등 사용자 체감 문제가 주요 확인 항목으로 언급됨.
- 수동 QA는 기능 정상 여부뿐 아니라 사용자가 실제로 불편하게 느끼는 흐름을 찾는 작업으로 정의함.

### 2.12 서비스 소개 및 인트로 인터랙션

- 서비스 소개와 인트로 화면의 스크롤 인터랙션 및 커서 효과를 계속 개선 중임을 공유함.
- 마우스 커서가 연필처럼 보이는 효과를 시도했고, 전체 방향성은 서비스 톤과 맞는다고 판단함.
- 위치, 타이밍, 문구 표시가 어색한 부분은 후속 보정이 필요함.
- 번역 문제는 전체 최적화 단계에서 정리하되, 우선은 인트로와 서비스 소개 인터랙션의 사용성과 완성도를 높이는 방향으로 진행하기로 함.

## 3. 결정 사항

- WebSocket 기반 실시간 기능은 점검 모드, 관리자 공지, 친구 presence, 쪽지, 협동 기능의 공통 기반으로 유지함.
- 관리자 점검 모드는 일반 사용자 차단과 ADMIN 우회 정책을 유지하고, 접속 중 사용자 반영은 WebSocket broadcast로 보완함.
- seed는 자동화하지 않고, 안전한 로컬 또는 데모 DB에서만 수동 실행함.
- schema 변경은 migration 파일과 함께 관리하고, main merge 후 CI/CD 흐름에서 production migration을 적용하는 기준을 유지함.
- Release와 tag는 기능 발전 흐름을 설명하는 자료로 활용하고, 한국어 간결체 문서 스타일을 유지함.
- 회원가입 음성 입력 제거, 비밀번호 안내 문구 개선, 닉네임 용어 통일, 헤더 간소화는 UX 안정화 범위로 관리함.
- 관리자 공지는 사용자가 직접 닫기 전까지 유지되는 배너 형태로 개선하는 방향을 채택함.
- 계정 제재는 새로고침 이후뿐 아니라 접속 중인 사용자에게도 즉시 반영되도록 개선함.
- 협동 퀘스트 기여도 입력은 숫자 직접 입력 외에 시간/타이머 기반 UX를 후속 후보로 검토함.
- 배포 환경 QA는 팀원이 실제 사용자처럼 기능을 눌러보고 문제를 기록하는 방식으로 계속 진행함.
