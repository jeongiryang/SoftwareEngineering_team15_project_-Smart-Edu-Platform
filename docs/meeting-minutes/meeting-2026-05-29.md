## 2. 논의 내용

### 2.1 로그인 UX 정리

- 로그인 화면에서 음성 입력 버튼이 꼭 필요한지 다시 검토함.
- 로그인 단계에서는 음성 입력보다 기본 입력 흐름의 안정성과 명확성이 더 중요하다고 판단함.
- 로그인 식별자는 실제 backend auth 구조상 email 기반이므로 schema/API를 바로 변경하지 않기로 함.
- 다만 사용자 화면에서는 `이메일`보다 `아이디` 표현이 더 익숙할 수 있어 UI 문구만 `아이디` 중심으로 정리하는 방향을 검토함.
- 이 경우 실제 저장 구조는 email 기반임을 유지하고, schema/migration/seed 변경은 발생시키지 않는 것이 안전하다고 판단함.
- 비밀번호 입력란에는 eye icon 기반 show/hide toggle을 추가하여 사용자가 입력값 마스킹 상태를 직접 확인할 수 있게 하는 방향을 논의함.
- 해당 토글은 키보드 접근, focus 상태, 접근성 label을 함께 고려해야 함.

### 2.2 헤더 구조와 언어 드롭다운 개편

- 기능이 많아지면서 로그인 후 헤더의 탭이 늘어나고 정보 구조가 복잡해진 점을 확인함.
- 상단 메뉴는 정부24처럼 관련 메뉴를 묶어 하위 항목을 보여주는 방식까지 참고하되, 현재 프로젝트 규모에 맞춰 과도한 mega-menu는 피하기로 함.
- `프로필` 직접 탭은 중복 진입점이므로 제거하고, 우측 사용자 영역의 `마이페이지` 진입을 중심으로 정리하는 방향을 검토함.
- `마이페이지`, `로그아웃`, 다크모드 토글, 언어 전환 메뉴가 서로 겹치지 않도록 우측 영역의 시각적 우선순위를 정리하기로 함.
- 언어 선택은 버튼을 나열하는 방식보다 `Language` 드롭다운 또는 compact 메뉴형 구조가 더 적합하다고 판단함.
- 헤더 개편 시 기존 route/history/F5 복원 흐름을 깨뜨리지 않는 것을 우선 기준으로 둠.

### 2.3 접근성 음성 선택 및 미리듣기

- 읽어주기 기능에서 사용자가 선택한 목소리가 실제 음성 출력에 반영되지 않는 것처럼 보이는 문제를 확인함.
- 브라우저 SpeechSynthesis voice 목록은 비동기적으로 로딩될 수 있으므로 `voiceschanged` 이벤트와 선택값 반영 타이밍을 함께 점검해야 함.
- 각 목소리 옵션에는 작은 speaker icon을 두고, 사용자가 선택 전에 짧게 미리듣기할 수 있도록 개선하는 방향을 논의함.
- 미리듣기 중복 재생을 막기 위해 기존 재생을 cancel하거나 stop하는 처리도 필요함.
- 본 실행 읽어주기와 미리듣기 음성이 충돌하지 않도록 재생 상태를 분리해 관리해야 함.
- 음성 기능은 브라우저/기기 환경에 따라 지원 범위가 다르므로 실패 시 사용자 친화적인 안내를 유지하기로 함.

### 2.4 커뮤니티 레이아웃 개선

- 현재 커뮤니티 화면에서 오른쪽 공간이 비어 보이거나 정보 밀도가 어색하게 느껴지는 문제를 확인함.
- 게시판형 UI에 가깝게 목록, 검색, 필터, 상세 영역의 시선 흐름을 다시 정리하는 방향을 논의함.
- 기존 게시글 CRUD, 댓글, 반응, 북마크, 신고 흐름은 유지해야 하며, 레이아웃 변경으로 기능 회귀가 발생하지 않아야 함.
- 웹 화면에서는 목록과 상세를 함께 볼 수 있게 하되, 모바일에서는 상세 패널이 화면을 과하게 차지하지 않도록 반응형 구조를 유지하기로 함.
- 다국어 적용 이후 커뮤니티 버튼, 검색, 필터, empty state 문구도 함께 점검해야 함.

### 2.5 마이페이지 및 프로필 구조 개선

- 프로필 대시보드는 여러 정보를 담고 있어 한눈에 보기 어렵다는 의견이 있었음.
- 닉네임 변경과 비밀번호 변경 같은 계정 설정은 처음부터 모두 펼쳐두기보다 요약 카드, 탭, 접기/펼치기, 모달 등으로 정리하는 방향을 검토함.
- 기존 닉네임 변경/비밀번호 변경 API, validation, inline feedback은 유지하되 UI 정보 구조만 다듬는 것이 적절하다고 판단함.
- `마이페이지` 진입 개념과 프로필 대시보드 화면 구성이 일관되도록 용어와 배치를 맞추기로 함.
- "현재 사용 중인 닉네임입니다" 같은 즉시 피드백은 유지하되, 화면 전체가 복잡해지지 않도록 표시 위치와 상태를 조정하기로 함.

### 2.6 대시보드 일정 및 할 일 미리보기

- 메인 대시보드에서 일정/할 일을 바로 확인할 수 있으면 사용성이 좋아질 것으로 판단함.
- 단, 기존 보상, 학습 자극, 1초 퀴즈, 커뮤니티, AI 진입 영역과 충돌하지 않도록 compact preview 형태가 적절하다고 논의함.
- 오늘 일정, 가까운 일정, 진행 중 태스크, 마감 임박 태스크를 간단히 보여주는 방식이 우선 후보로 정리됨.
- 대시보드 미리보기는 전체 일정/칸반 기능을 대체하지 않고, 해당 화면으로 이동하는 짧은 연결 역할을 하도록 설계하기로 함.

### 2.7 일정 화면 구조 정리

- 일정 화면은 생성 폼, 월간 달력, 리마인더, 일정 목록, 우선순위 정보가 함께 있어 시선 흐름이 복잡해질 수 있음을 확인함.
- 정보 밀도는 유지하되, 섹션 제목과 요약 카드, 목록 순서를 정리해 화면 목적이 더 명확히 보이도록 개선하기로 함.
- 일정 생성 validation과 inline feedback은 유지하고, 입력 흐름과 결과 목록의 관계가 더 자연스럽게 보이도록 정리하는 방향을 논의함.
- D-Day 계획, 복습 알림, 기존 일정 목록이 서로 충돌하지 않도록 화면 구조를 유지해야 함.

### 2.8 다국어 전수 점검 필요

- 다국어 전환 기능이 추가된 뒤 일부 화면에서 한국어와 다른 언어가 한 문장 안에 섞이는 문제가 발생할 수 있음을 확인함.
- `지Fri`, `지週五`처럼 부분 문자열 치환으로 생기는 혼합 번역은 문장 단위 key 또는 locale 기반 formatter로 정리해야 함.
- Landing/Login 타이핑 문구, AppHeader, Dashboard, Profile, Statistics, Community, Friends, Schedule, TaskBoard, Reward, Shop, AI 화면을 전수 점검 대상으로 둠.
- AI mock/demo 응답, OCR/PDF mock 결과, token/quota/API key/network 오류 안내도 선택 언어를 반영하는지 확인해야 함.
- footer 문구는 언어에 따라 번역하지 않고 아래 고정 문구를 유지하기로 함.
  - `© 2026 CWNU Software Engineering Team 15 · 사각사각`
  - `Personalized Smart Edu Platform`
- English, 日本語, 中文은 Beta 언어로 표시하되, Beta는 언어 선택 UI에서만 작게 보여주는 방향을 유지하기로 함.

### 2.9 local migration/seed 적용 승인 기준

- schema/migration 변경이 실제로 필요한 작업과 단순 UI 문구 변경을 구분하기로 함.
- auth 식별자 구조처럼 schema/API/seed 영향이 큰 변경은 충분히 검토한 뒤 별도 Issue/PR로 분리해야 함.
- 사용자는 개인 로컬 개발 DB 기준 migration 및 seed 적용을 승인했으나, 운영/공유 DB에는 임의로 실행하지 않는 원칙을 유지함.
- schema 변경 PR이 main에 merge된 뒤에는 최신 main 기준으로 `npx prisma migrate deploy`를 사용할 수 있음.
- seed 변경 PR이 main에 merge된 뒤에는 최신 main 기준으로 `npm run seed:dev`를 실행할 수 있음.
- DB URL, token, API key, JWT secret 등 민감정보는 출력하지 않기로 함.
- migration/seed 실행 방법은 관련 PR 본문 또는 코멘트에 명확히 남기기로 함.
