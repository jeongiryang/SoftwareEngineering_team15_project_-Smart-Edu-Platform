## 2. 주요 논의 내용

### 2.1 관리자 API와 AI 학습 지원 MVP API 검토

- 황대겸이 관리자 기능 API와 AI 학습 지원 MVP API 관련 PR을 생성함.
- 정이량은 두 PR을 Codex 기준으로 검토하고 보완 후 merge함.
- 관리자 기능 API는 권한 검증, 미인증/일반 사용자 접근 차단, 민감정보 미노출, 예외 처리 테스트를 보강한 뒤 main에 반영함.
- AI 학습 지원 MVP API는 초기 검토에서 schema 변경 누락 문제가 발견되어 바로 merge하지 않고 재작업함.
- AI 기능과 직접 관련 없는 `schema.prisma` 변경은 제거하고, migration 없는 schema 변경이 남지 않도록 정리함.
- 최종적으로 관리자 API와 AI MVP API 모두 main에 반영됨.

### 2.2 API 명세 문서와 테스트 보고서 관리 기준

- 조원은 원칙적으로 기능 구현과 PR 생성을 우선하기로 함.
- `docs/api/api-spec.md`와 `docs/test-report/test-report.md`는 정이량이 PR 검증/보완 단계에서 최종 갱신하기로 함.
- 조원이 문서를 함께 수정한 경우에도 PR 검증 과정에서 실제 구현과 맞는지 확인한 뒤 반영 여부를 판단하기로 함.

### 2.3 schema / migration 변경 주의사항

- PR에서 schema 변경 여부를 정확히 명시해야 함을 다시 강조함.
- schema 변경이 있었는데 PR 본문에 "schema/migration 변경 없음"으로 적으면 DB 구조 판단에 문제가 생길 수 있음.
- schema 변경 여부에 따라 migration 필요 여부가 달라지므로, 변경 파일을 정확히 확인하고 PR 본문에 명시해야 함.
- schema/migration 변경이 있는 경우 아래 내용을 PR 본문에 반드시 적기로 함.
  - 변경 사유
  - 변경된 모델/필드/관계
  - migration 파일 생성 여부
  - 영향받는 API
  - 테스트 결과
  - 특이사항
- production DB에서 `migrate dev`, `seed:dev`, `test:db` 실행은 금지함.

### 2.4 AI API 테스트 및 한도 리스크

- 황대겸은 Gemini API key를 본인 `.env`에 넣어 직접 테스트했다고 공유함.
- AI API는 Gemini 기준으로만 테스트했으며, 다른 AI provider는 아직 테스트하지 않음.
- 무료 한도와 사용량 제한 문제를 고려하여 아래 방향으로 관리하기로 함.
  - 프롬프트 입력 길이 제한
  - 호출 횟수 제한
  - fallback 처리
  - 앱이 어느 정도 완성된 뒤 실제 질문을 넣어 품질 확인
- AI API key는 프론트엔드에 절대 넣지 않고, 백엔드 `.env`에서만 관리함.
- 프론트엔드는 외부 AI provider를 직접 호출하지 않고, 백엔드 AI API만 호출하도록 함.
- AI 학습 지원 기능은 제한적 MVP로 보고, 실제 품질과 비용 문제는 후속 개선 대상으로 둠.

### 2.7 관리자 화면 연결 방향

황대겸은 관리자 API를 프론트 화면에 어떻게 연결할지 질문함.

정리된 방향:

- 기존 로그인/대시보드 흐름은 유지함.
- Dashboard에서 관리자 화면으로 이동할 수 있게 함.
- 로그인 사용자가 ADMIN인지 확인함.
- ADMIN 사용자만 관리자 화면 접근 가능하게 처리함.
- 일반 USER는 관리자 화면에 접근하지 못하게 함.
- 관리자 API를 호출하여 사용자 목록, 사용자 상태 변경, 게시글/댓글/신고 관리 등을 연결함.
- 최종 디자인보다 기능 연결을 우선함.
- 로딩/에러 상태를 표시함.

### 2.8 AI 학습 지원 화면 연결 방향

AI 화면 연결 방향은 아래처럼 정리함.

- AI 질문/응답 화면을 추가함.
- 백엔드 AI 학습 지원 API만 호출함.
- 프론트엔드에 `AI_API_KEY`를 넣지 않음.
- API key, token 원문을 화면/로그에 노출하지 않음.
- AI 요청 중 로딩 상태를 표시함.
- 실패 시 fallback 응답 또는 에러 메시지를 표시함.
- 최종 UI/UX보다 기능 연결을 우선함.

### 2.9 관리자 화면 작업 중 발견된 이슈

  - 프론트 상태 갱신이 누락되었는지
  - 목록 재조회가 필요한지
  - 백엔드 상태 변경 로직과 프론트 표시 정책이 일치하는지
  - 신고 기각/취소 정책이 문서와 맞는지

### 2.10 PR 작성 및 연결 규칙

- 조원들은 PR을 올릴 때 본인이 맡은 관련 Issue를 PR 본문에 연결하기로 함.
- `Closes #이슈번호`를 PR 본문에 적으면 merge 시 해당 Issue가 자동으로 닫힘.
- 변경 파일을 정확히 명시해야 함.
- schema/migration 변경 여부는 반드시 명시해야 함.
- 정이량은 PR을 바로 merge하지 않고, Codex로 구조/보안/테스트/문서/schema 영향을 검증한 뒤 main에 반영함.

### 2.11 관리자 화면 연결 PR #75 처리

- 황대겸이 관리자 화면 연결 작업을 진행함.
- 관리자 화면에서 사용자 상태 변경 흐름을 확인함.
  - 사용자 정지
  - 사용자 활성화
  - 사용자 비활성화
- 관리자 조치 기록이 로그에 남는 것을 확인함.
- 관리자 화면은 사용자 관리와 제재/상태 변경 중심으로 동작하며, 게시판/챌린지 관련 기능은 후속 기능 구현 상태에 따라 확장될 수 있음.
- PR #75 `[feat] 관리자 화면 연결`이 생성되었고, Codex 기준 검토, 보완, 수동 확인 후 main에 merge됨.
- PR #75 검토 과정에서 한글 comment 인코딩 깨짐 문제가 발생했으며, 이후 한국어 comment는 UTF-8 body file 방식으로 작성하는 방향으로 정리함.
- PR #75에서는 사용하지 않는 API 함수, whitespace, unused import 등을 정리한 뒤 merge함.

### 2.12 관리자 화면 작업 중 확인한 이슈와 처리

- 신고 기각/취소 후 목록이 갱신되지 않는 문제가 작업 중 언급됨.
- 해당 문제는 PR #75 검증 과정에서 처리 후 `loadData(true)` 등을 통해 목록 재조회 흐름을 확인함.
- 수동 테스트에서 관리자 화면 진입, 일반 USER 접근 차단, 로그아웃 후 접근 차단, 신고 기각/취소 후 목록 갱신을 확인함.
- 관리자 화면은 최종 UI/UX가 아니라 기능 연결 중심으로 구현됨.

### 2.13 AI 학습 지원 화면 연결 작업 진행

- 황대겸이 #72 AI 학습 지원 화면 연결 작업을 이어서 진행함.
- AI 질문 생성이 정상 동작하는 것을 확인함.
- AI 학습 지원 화면은 백엔드 AI API를 호출하는 방향으로 진행함.
- 프론트엔드에는 `AI_API_KEY`를 넣지 않고, 프론트는 백엔드 API만 호출하는 구조를 유지하기로 함.
- AI 화면은 로딩, 에러, fallback 응답을 표시하는 방향으로 구현하기로 함.

### 2.14 AI 응답 언어 문제와 한국어 우선 처리

- 맞춤 학습 추천, 오답 원인 분석 등 일부 AI 응답이 영어로 반환되는 문제가 확인됨.
- 해결 방향으로 프롬프트 또는 백엔드 AI API 구현부에서 한국어 응답을 우선하도록 강제하는 방안을 검토함.
- 기능 구현상 필요한 경우 백엔드 AI API 구현부를 수정할 수 있으나, PR 본문에 반드시 변경 파일과 이유를 명시하기로 함.
- 최종적으로 우선 한국어 응답 안정화를 목표로 진행하기로 함.
- AI 응답 품질은 앱 기능이 어느 정도 완성된 뒤 실제 질문을 넣어가며 추가 보완하기로 함.

### 2.15 학습 전용 프롬프트와 다국어 지원 방향

- AI 학습 지원 기능은 일반 잡담형 AI가 아니라 학습 보조용 AI로 방향을 잡기로 함.
- 학습 관련 질문은 자세히 응답하고, 학습과 관련 없는 질문은 짧게 응답한 뒤 학습 관련 질문을 유도하는 방향을 검토함.
- 전용 학습 프롬프트는 후속 보완 대상으로 남김.
- 다국어 지원 가능성도 논의되었으며, 후보 언어로 한국어, 영어, 중국어, 일본어 등이 언급됨.
- 다만 현재 단계에서 전체 UI 다국어 처리는 화면 문구, 언어 설정, AI 응답 언어, 프론트 상태 관리가 함께 얽혀 작업 범위가 커질 수 있다고 판단함.
- 따라서 현재는 한국어 응답과 한국어 UI 안정화를 우선하고, 다국어 지원은 기능 구현이 어느 정도 완료된 뒤 UI/UX 단계에서 후순위로 검토하기로 함.
- 큰 구조 변경 없이 가능한 범위라면 추후 검토할 수 있음.

### 2.16 PR 생성, 작업 보호, PR #76 주의사항

- 정이량은 조원에게 모든 테스트를 끝낸 뒤 PR을 올리는 것뿐 아니라, 작업 브랜치를 안전하게 원격에 올려 PR을 먼저 만들어두는 방식도 가능하다고 안내함.
- 이는 로컬 브랜치 삭제나 AI 에이전트 실수로 작업물이 유실될 위험을 줄이기 위한 방식임.
- 다만 황대겸은 본인이 최종 검증 후 책임지고 PR을 생성하겠다고 함.
- PR을 생성할 때는 관련 Issue를 `Closes #번호`로 연결하고, 변경 파일과 특이사항을 정확히 적기로 함.
- 황대겸이 PR #76을 생성함.
- PR #76은 AI 학습 지원 화면 연결 및 AI 응답 한국어 처리 관련 후속 작업으로 보임.
- 황대겸은 PR #76이 현재 main 기준에서 충돌 가능성이 있을 수 있음을 알림.
- PR #76 검토 시 #67 merge 이후 main 기준과 #75 merge 이후 변경사항이 반영되었는지 확인이 필요함.
- 이후 PR #76 검증 시 특히 아래 항목을 확인하기로 함.
  - #72 관련 Issue 연결 여부
  - 최신 main 반영 여부
  - #75 관리자 화면 변경을 덮어쓰지 않았는지 여부
  - AI 응답 한국어 처리 방식
  - 프론트엔드 `AI_API_KEY` 노출 여부
  - 백엔드 AI API 수정 여부와 PR 본문 명시 여부
  - 다국어 지원이 과도하게 확장되지 않았는지 여부
  - 자동 테스트에서 실제 외부 AI API 호출이 없는지 여부
