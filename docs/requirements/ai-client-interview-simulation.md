## 1. 문서 개요

본 문서는 Smart Edu Platform을 만들어달라고 요구하는 공식 의뢰자와 의뢰 조직 주변 이해관계자의 관점을 정리한 AI 기반 인터뷰 시뮬레이션 문서임.

공식 의뢰자와 이해관계자는 시스템 액터가 아니라 요구사항 도출 근거 제공자임. 본 문서는 공식 의뢰자와 이해관계자 관점에서 Smart Edu Platform의 요구사항 타당성, 우선순위, 운영성, 확장성, 보안성을 검토한 근거 자료임.

---

## 2. 고객 개념 정의

본 프로젝트에서 고객은 Smart Edu Platform을 직접 사용하는 최종 사용자뿐 아니라, 해당 서비스를 기획·의뢰·운영·관리하는 사람 또는 조직까지 포함함.

고객 관점은 다음 두 범위로 구분함.

- 최종 사용자: 실제로 학습 관리 기능을 사용하는 학습자
- 서비스 의뢰자/이해관계자: 서비스를 기획, 의뢰, 운영, 보안 검토, 사업화하는 사람 또는 조직

## 4. 사업 배경 및 최종 목표

기존 학습 앱은 특정 연령대나 특정 목적에 치중된 경우가 많음.

공공·평생교육기관은 초등학생부터 시니어 학습자까지 다양한 연령층을 포괄하는 디지털 학습 관리 환경이 필요함.

본 프로젝트는 특정 강의 판매 플랫폼이 아니라, 학습 일정, 태스크, AI 학습 지원, 집중 시간, 통계, 커뮤니티 기능을 통합하는 **학습 관리 플랫폼 시범사업**으로 설정함.

## 6. 공식 의뢰자 인터뷰 시뮬레이션

공식 의뢰자 인터뷰는 다음 질문을 기준으로 정리함.

- Q1: 이 사업을 추진하게 된 배경은 무엇입니까?
- Q2: 이 학습 관리 플랫폼의 최종 목표는 무엇입니까?
- Q3: 초기 단계에서 가장 우선해야 하는 기능이나 품질은 무엇입니까?
- Q4: 운영 기관 관점에서 가장 우려되는 점은 무엇입니까?
- Q5: 이 서비스가 성공했다고 판단할 기준은 무엇입니까?

### 6.1 공공·평생교육기관 기반 디지털 학습 관리 플랫폼 시범사업 책임자

- A1(추진 배경): 기존 학습 앱은 수험생, 초등학생, 직장인처럼 특정 집단에 치우친 경우가 많음. 공공·평생교육기관 관점에서는 초등학생부터 시니어 학습자까지 다양한 사용자가 같은 플랫폼 안에서 자기 목적에 맞게 학습을 관리할 수 있어야 함.
- A2(최종 목표): 최종 목표는 강의 판매 플랫폼이 아니라 개인별 학습 계획, 태스크, 기록, 복습, 커뮤니티를 통합하는 학습 관리 환경을 만드는 것임. 사용자가 연령과 목적에 따라 다른 기능을 우선적으로 활용하되, 기본 학습 기록은 일관되게 관리되는 구조가 필요함.
- A3(우선순위): 초기 단계에서는 사용자 유형별 기능 제공, 일정/태스크 관리, 학습 기록, AI 학습 질의, 통계 확인이 우선임. 기능을 넓게 나열하는 것보다 학습 계획에서 기록과 복습까지 이어지는 기본 흐름이 안정적으로 동작하는지가 중요함.
- A4(운영 우려): 운영 기관 입장에서는 학습 지속성, 기록 보존, 게시판 관리, 사용자 제재 같은 관리 흐름이 우려됨. 특히 커뮤니티와 챌린지는 참여를 높일 수 있지만, 신고 처리와 운영 기준이 없으면 관리 부담이 커질 수 있음.
- A5(성공 기준): 다양한 사용자 그룹이 자기 목적에 맞는 기능을 찾고, 학습 기록과 복습 루틴을 꾸준히 남길 수 있으면 성공 가능성이 높다고 판단함. 또한 개인정보 보호, 권한 관리, 기록 신뢰성이 확보되어야 기관에서 시범사업으로 운영할 수 있음.
- 연결 요구사항: FR-01, FR-02, FR-03, FR-04, FR-07, FR-16, FR-23, FR-27, FR-28, FR-29, NFR-02, NFR-03, NFR-07, NFR-12

## 7. 이해관계자별 인터뷰 시뮬레이션

이해관계자 인터뷰는 다음 공통 질문을 기준으로 정리함.

- Q1: 담당 관점에서 가장 중요하게 보는 문제는 무엇입니까?
- Q2: 이 서비스에서 우선적으로 확인해야 할 기능이나 품질은 무엇입니까?
- Q3: 해당 기능이 왜 필요한가요?
- Q4: 운영, 확장, 보안, 사용자 경험 측면에서 주의할 점은 무엇입니까?
- Q5: 이 관점에서 기존 요구사항 중 가장 중요하게 보는 항목은 무엇입니까?

### 7.1 서비스 기획자

#### 7.1.1 서비스 기획자 A

- A1(핵심 문제): 사용자 유형이 넓어 모든 사용자에게 같은 첫 화면을 제공하면 필요한 기능을 찾기 어려울 수 있음.
- A2(우선 확인 항목): 사용자 유형별 기능 제공과 초기 화면의 기능 우선순위를 먼저 확인해야 함.
- A3(필요 이유): 초등학생은 보상과 쉬운 화면, 수험생은 오답과 통계, 직장인은 요약과 TTS처럼 우선순위가 다르기 때문임.
- A4(주의점): 화면 분기가 너무 복잡하면 관리와 구현이 어려워질 수 있으므로 기본 구조는 단순해야 함.
- A5(중요 요구사항): 사용자 유형별 기능 제공이 가장 중요함.
- 연결 요구사항: FR-23, FR-20, FR-25

#### 7.1.2 서비스 기획자 B

- A1(핵심 문제): MVP에서 기능을 넓게 넣기만 하면 사용자가 실제 학습 흐름을 이어가기 어려울 수 있음.
- A2(우선 확인 항목): 일정 등록, 태스크 관리, AI 질의, 집중 기록이 하나의 학습 흐름으로 연결되는지 확인해야 함.
- A3(필요 이유): 학습 계획을 세우고 실행한 뒤 기록과 복습으로 이어져야 플랫폼의 기본 가치가 드러남.
- A4(주의점): AI 기능이 앞에 나와도 일정과 기록 흐름이 약하면 학습 관리 앱으로서의 정체성이 흐려질 수 있음.
- A5(중요 요구사항): 일정 관리, 칸반 보드, AI 학습 질의, 스톱워치/타이머를 우선적으로 봄.
- 연결 요구사항: FR-03, FR-04, FR-07, FR-15

#### 7.1.3 서비스 기획자 C

- A1(핵심 문제): 초등학생과 시니어는 같은 기능도 화면 표현 방식이 맞지 않으면 사용을 포기할 가능성이 높음.
- A2(우선 확인 항목): 큰 글씨, 고대비, 아이콘 중심 UI, 사용자 유형별 기능 제공을 함께 확인해야 함.
- A3(필요 이유): 접근성은 별도 옵션이 아니라 넓은 사용자층을 포괄하는 서비스에서 기본 사용성에 해당함.
- A4(주의점): 접근성 설정이 깊은 메뉴 안에 숨으면 실제 사용자가 찾기 어려우므로 초기 접근성이 중요함.
- A5(중요 요구사항): 큰 글씨/고대비 모드와 아이콘 중심 UI를 중요하게 봄.
- 연결 요구사항: FR-20, FR-23, FR-25

#### 7.1.4 서비스 기획자 D

- A1(핵심 문제): 학습 관리 플랫폼이 강의 판매나 콘텐츠 제공 중심으로 보이면 현재 프로젝트 목적과 달라질 수 있음.
- A2(우선 확인 항목): 사용자가 직접 계획을 세우고, 할 일을 완료하고, 기록을 확인하는 흐름을 우선 확인해야 함.
- A3(필요 이유): 학습 지속성은 콘텐츠 양보다 계획과 기록을 계속 반복할 수 있는 구조에서 만들어짐.
- A4(주의점): 통계와 보상은 부가 기능처럼 보일 수 있지만 학습 루틴을 유지하는 피드백으로 연결되어야 함.
- A5(중요 요구사항): 학습 일정 관리, 순공 시간 측정, 학습 데이터 시각화를 중요하게 봄.
- 연결 요구사항: FR-03, FR-15, FR-16

### 7.2 교육기관/학원 운영자

#### 7.2.1 교육기관 운영자 A

- A1(핵심 문제): 학습자가 중간에 포기하는 경우가 많아 지속성을 유지하는 장치가 필요함.
- A2(우선 확인 항목): 보상과 스터디 챌린지가 실제 참여를 높이는지 확인해야 함.
- A3(필요 이유): 작은 보상과 공동 목표가 있으면 초등학생이나 중학생이 학습을 게임처럼 받아들일 수 있음.
- A4(주의점): 보상은 학습 목표 달성과 연결되어야 하며 단순 클릭 보상처럼 보이면 효과가 떨어질 수 있음.
- A5(중요 요구사항): 스터디 챌린지와 퀘스트/뱃지/포인트를 중요하게 봄.
- 연결 요구사항: FR-12, FR-24

#### 7.2.2 학원 운영자 B

- A1(핵심 문제): 수업 직후에는 이해한 것처럼 보여도 며칠 지나면 내용을 잊는 경우가 많음.
- A2(우선 확인 항목): 주기적 복습 알림과 노트 기반 복습 흐름을 확인해야 함.
- A3(필요 이유): 학원이나 교육기관은 수업 시간 밖에서도 학습자가 다시 복습하도록 유도해야 함.
- A4(주의점): 알림이 너무 잦으면 사용자가 꺼버릴 수 있으므로 학습 기록 기반으로 적절한 시점에 제공되어야 함.
- A5(중요 요구사항): 주기적 복습 알림을 중요하게 봄.
- 연결 요구사항: FR-26, FR-06

#### 7.2.3 교육기관 운영자 C

- A1(핵심 문제): 운영자는 학습자가 실제로 참여하고 있는지 감으로만 판단하기 어려움.
- A2(우선 확인 항목): 학습 시간, 진척도, 히트맵 같은 기록 시각화를 확인해야 함.
- A3(필요 이유): 기록이 쌓이면 상담, 학습 방향 조정, 프로그램 효과 확인에 활용할 수 있음.
- A4(주의점): 통계는 학습자를 감시하는 느낌이 아니라 자기 점검과 운영 참고 자료로 보여야 함.
- A5(중요 요구사항): 학습 데이터 시각화와 학습 히트맵을 중요하게 봄.
- 연결 요구사항: FR-16, FR-17

#### 7.2.4 학원 운영자 D

- A1(핵심 문제): 수업 외 질문이 채팅방이나 개인 메시지에 흩어지면 반복 대응이 많아짐.
- A2(우선 확인 항목): 질문 게시판, 댓글, 카테고리별 게시판 구조를 확인해야 함.
- A3(필요 이유): 같은 질문과 답변이 축적되면 다른 학습자도 참고할 수 있어 운영 효율이 높아짐.
- A4(주의점): 게시판을 열면 운영 관리도 함께 필요하므로 신고와 관리 흐름이 분리되어야 함.
- A5(중요 요구사항): 카테고리별 게시판과 게시판 운영 관리를 중요하게 봄.
- 연결 요구사항: FR-13, FR-27

### 7.3 학습 플랫폼 관리자

#### 7.3.1 플랫폼 관리자 A

- A1(핵심 문제): 게시판이 운영되면 부적절한 글, 댓글, 신고 처리 문제가 반드시 발생함.
- A2(우선 확인 항목): 게시글, 댓글, 신고된 게시물을 확인하고 처리하는 관리 기능을 확인해야 함.
- A3(필요 이유): 질문, 자유, 학습 인증 게시판은 사용자 참여를 높이지만 관리 기준이 없으면 품질이 빠르게 낮아질 수 있음.
- A4(주의점): 관리 기능은 일반 사용자 화면과 구분되어야 하며 처리 상태를 추적할 수 있어야 함.
- A5(중요 요구사항): 게시판 운영 관리를 중요하게 봄.
- 연결 요구사항: FR-27

#### 7.3.2 플랫폼 관리자 B

- A1(핵심 문제): 부적절한 계정을 처리할 때 사유와 기록이 없으면 운영 일관성이 떨어짐.
- A2(우선 확인 항목): 사용자 계정 관리와 제재 기록 흐름을 확인해야 함.
- A3(필요 이유): 계정 제재는 사용자 경험과 직접 연결되므로 근거와 기간이 명확해야 함.
- A4(주의점): 제재 기능은 과도하게 사용되지 않도록 관리자 권한과 처리 사유가 분리되어야 함.
- A5(중요 요구사항): 사용자 계정 관리 및 제재를 중요하게 봄.
- 연결 요구사항: FR-28

#### 7.3.3 플랫폼 관리자 C

- A1(핵심 문제): 스터디 챌린지도 허위 인증이나 부적절한 목표 설정으로 운영 문제가 생길 수 있음.
- A2(우선 확인 항목): 챌린지 확인, 관리, 처리 상태 기록 기능을 확인해야 함.
- A3(필요 이유): 챌린지는 학습 지속성을 높이는 기능이지만 운영 기준이 없으면 사용자 간 신뢰가 낮아짐.
- A4(주의점): 챌린지 관리는 학습자 참여를 위축시키지 않는 범위에서 최소한으로 작동해야 함.
- A5(중요 요구사항): 스터디 챌린지 관리를 중요하게 봄.
- 연결 요구사항: FR-29

#### 7.3.4 플랫폼 관리자 D

- A1(핵심 문제): 관리자 기능이 일반 사용자 기능과 섞이면 권한 오류와 오조작 위험이 생김.
- A2(우선 확인 항목): 관리자 권한과 일반 사용자 권한이 분리되는지 확인해야 함.
- A3(필요 이유): 관리자는 게시글, 계정, 챌린지를 다루므로 접근 범위가 명확해야 함.
- A4(주의점): 권한 요청과 관리자 기능 접근은 보안 기준과 함께 설계되어야 함.
- A5(중요 요구사항): 게시판 관리, 사용자 제재, 챌린지 관리, 권한 관리를 중요하게 봄.
- 연결 요구사항: FR-27, FR-28, FR-29, NFR-07

### 7.4 데이터/보안 담당자

#### 7.4.1 데이터/보안 담당자 A

- A1(핵심 문제): 이메일, 프로필, 학습 기록, 활동 로그가 함께 저장되면 개인정보 보호가 중요해짐.
- A2(우선 확인 항목): 개인정보 보호 기준과 데이터 접근 범위를 확인해야 함.
- A3(필요 이유): 학습 데이터는 단순 기록이 아니라 개인의 생활 패턴과 성향을 드러낼 수 있음.
- A4(주의점): 통계나 추천 기능에 데이터를 활용하더라도 외부 노출과 과도한 접근은 제한되어야 함.
- A5(중요 요구사항): 개인정보 보호를 중요하게 봄.
- 연결 요구사항: NFR-03

#### 7.4.2 데이터/보안 담당자 B

- A1(핵심 문제): 인증이 약하면 사용자 계정과 학습 기록이 함께 위험해질 수 있음.
- A2(우선 확인 항목): 이메일/비밀번호 기반 로그인과 비밀번호 암호화 기준을 확인해야 함.
- A3(필요 이유): 인증 흐름은 간단해야 하지만 비밀번호 저장 방식은 안전해야 함.
- A4(주의점): 사용자가 어려워하지 않는 로그인 흐름과 기본 보안 기준 사이 균형이 필요함.
- A5(중요 요구사항): 비밀번호 암호화를 중요하게 봄.
- 연결 요구사항: FR-01, NFR-02

#### 7.4.3 데이터/보안 담당자 C

- A1(핵심 문제): 캘린더, 파일, 미디어 같은 권한은 사용자의 민감 정보와 연결될 수 있음.
- A2(우선 확인 항목): 사용자 동의 기반 권한 요청 흐름을 확인해야 함.
- A3(필요 이유): 외부 캘린더 연동이나 노트 첨부 기능은 편리하지만 권한 요청 사유가 명확해야 함.
- A4(주의점): 권한 요청은 기능 사용 시점에 필요한 이유와 함께 제시되어야 함.
- A5(중요 요구사항): 사용자 동의 기반 권한 요청을 중요하게 봄.
- 연결 요구사항: FR-22, NFR-07

#### 7.4.4 데이터/보안 담당자 D

- A1(핵심 문제): 학습 기록이 손실되면 통계, 보상, 복습 알림의 신뢰성이 함께 떨어짐.
- A2(우선 확인 항목): 학습 기록 보존과 데이터 신뢰성 기준을 확인해야 함.
- A3(필요 이유): 학습 시간, 오답, 복습 기록은 장기적인 학습 관리의 근거가 됨.
- A4(주의점): 기록 저장은 기능별로 흩어지지 않고 일관된 데이터 구조에서 관리되어야 함.
- A5(중요 요구사항): 학습 기록 보존을 중요하게 봄.
- 연결 요구사항: NFR-12, FR-16, FR-17

### 7.5 에듀테크 사업 책임자

#### 7.5.1 사업 책임자 A

- A1(핵심 문제): AI 기능이 단순 답변에 머물면 학습 관리 플랫폼의 차별성이 약해질 수 있음.
- A2(우선 확인 항목): AI 질의, 오답노트, 학습 추천, 퀴즈 생성이 학습 효과와 연결되는지 확인해야 함.
- A3(필요 이유): 사용자가 AI를 통해 약점을 찾고 다시 복습하는 흐름이 생겨야 실제 학습 성과로 이어질 수 있음.
- A4(주의점): AI 결과는 과도하게 확정적으로 보이기보다 학습 보조 자료로 활용되는 흐름이 적절함.
- A5(중요 요구사항): AI 학습 질의, AI 오답노트, AI 학습 추천, AI 기반 퀴즈 생성을 중요하게 봄.
- 연결 요구사항: FR-07, FR-08, FR-09, FR-10

#### 7.5.2 사업 책임자 B

- A1(핵심 문제): 학습자는 항상 화면을 오래 볼 수 있는 상황에서 공부하지 않음.
- A2(우선 확인 항목): TTS와 요약 기능이 직장인, 시니어 학습자, 이동 중 학습자에게 도움이 되는지 확인해야 함.
- A3(필요 이유): 같은 학습 내용이라도 듣기와 요약이 제공되면 접근성과 자투리 시간 활용성이 높아짐.
- A4(주의점): 요약은 학습 내용을 지나치게 단순화하지 않아야 하고, 음성 학습은 속도와 가독성을 고려해야 함.
- A5(중요 요구사항): 텍스트 읽어주기와 학습 내용 요약을 중요하게 봄.
- 연결 요구사항: FR-18, FR-19

#### 7.5.3 사업 책임자 C

- A1(핵심 문제): 사용자층이 넓은 서비스는 한 가지 화면과 기능 우선순위로는 시장 적합성을 확보하기 어려움.
- A2(우선 확인 항목): 사용자 유형별 기능 제공과 접근성 설정을 확인해야 함.
- A3(필요 이유): 초등학생, 고등학생, 직장인, 시니어 학습자는 같은 학습 관리 기능도 다른 방식으로 접근함.
- A4(주의점): 개인화가 복잡한 설정으로 느껴지면 사용자가 포기할 수 있으므로 기본 유형 선택이 단순해야 함.
- A5(중요 요구사항): 사용자 유형별 기능 제공을 중요하게 봄.
- 연결 요구사항: FR-23, FR-20, FR-25

#### 7.5.4 사업 책임자 D

- A1(핵심 문제): 학습 기록이 계속 누적되는 서비스는 초기 구조가 불안정하면 확장 단계에서 문제가 커질 수 있음.
- A2(우선 확인 항목): 기능 모듈화, 학습 기록 보존, 안정적인 API/DB 설계 방향을 확인해야 함.
- A3(필요 이유): 일정, 오답, 집중 시간, 통계, 보상 기록이 서로 연결되므로 데이터 신뢰성이 서비스 품질에 직접 영향을 줌.
- A4(주의점): 초기 MVP라도 기록 구조와 API 흐름은 이후 기능 확장을 고려해 정리되어야 함.
- A5(중요 요구사항): 기능 모듈화와 학습 기록 보존을 중요하게 봄.
- 연결 요구사항: NFR-09, NFR-12

## 9. 기존 요구사항과의 연결

의뢰자/이해관계자 인터뷰 결과는 요구사항 문서에 정리된 기능과 품질 기준의 필요성을 보강하는 근거로 사용함.

특히 운영, 보안, 관리자 기능은 실제 사용자 인터뷰만으로는 충분히 드러나기 어려운 영역임. 따라서 본 문서는 요구사항의 타당성, 우선순위, 운영성, 확장성, 보안성 검토 자료로 활용함.

---

## 10. 정리

서비스 의뢰자와 이해관계자 관점은 시스템 액터가 아니라 요구사항 근거 제공자임.

따라서 본 문서의 결과는 서비스 사용자 관점만으로는 확인하기 어려운 운영성, 확장성, 보안성, 관리 기능 우선순위를 설명하는 보조 근거로 활용함.
